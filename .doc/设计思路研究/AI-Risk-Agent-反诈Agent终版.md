# 银龄盾 · 反诈 Agent(终版)

> **这不是一个 AI 监测系统,而是一个会持续进化、长期守护一位老人的反诈 Agent。**

---

## 产品哲学(开篇就讲清)

> **AI 不是决策者,而是「帮助老人相信正确的人」。**

```
不是: AI: "这是诈骗。"
而是: AI: "建议联系您的儿子确认。"
       或
       AI: "社区工作人员已经帮您核验,该活动不存在备案。"
```

防诈骗真正的难点,从来不是识别 —— 而是 **让老人愿意接受帮助**。
被骗的老人对「陌生人」反而建立了信任,对「AI 提醒」反而抗拒。
所以我们的 Agent 不是替老人做判断,而是 **帮老人找到他愿意相信的那个人,让那个人来传达判断**。

这是整个产品的灵魂,也是它区别于所有「AI 识别系统」的根本。

---

## 项目定位(贯穿全文的一句话)

> **我们构建的不是一个反诈 AI 功能,而是一个反诈 Agent(Elder Fraud Agent)。**
>
> 这个 Agent 拥有 **七层循环感知与推理能力**(Perceive→Understand→Predict→Reason→Decide→Act→Learn)、**一份长期维护的数字老人画像(Digital Elder Profile)**、**一条反馈驱动的持续进化闭环**,并在 **老人-家属-社区** 三方之间充当 **信任的桥梁**。

---

## 一、系统核心竞争力(8 项 · vs 市面方案)

> **不写功能写能力。这是这一页存在的意义。**

| # | 能力维度 | 市面方案 | **银龄盾反诈 Agent** |
| --- | --- | --- | --- |
| 1 | **连续感知** | 单点检测 | **全流程持续感知**(7×24 主动采集 + 异常触发) |
| 2 | **可解释 AI** | 黑盒预警 | **多模态证据链 + LLM 解释**(每条预警都有可读理由) |
| 3 | **智能决策** | 固定规则 | **Rule + ML + LLM 三层决策**(毫秒级 + 概率化 + 可解释) |
| 4 | **长期记忆** | 无 | **数字老人画像(Digital Elder Profile)**(每位老人独立持久化) |
| 5 | **主动学习** | 无 | **反馈驱动的闭环持续优化**(误报降权、漏报升权、画像自适应) |
| 6 | **多方协同** | 单人提醒 | **老人-家属-社区分级响应**(根据可达性动态选资源) |
| 7 | **信任增强** | 强制提醒 | **可解释 + 第三方验证 + 长期陪伴**(让老人愿意相信) |
| 8 | **服务闭环** | 通知即结束 | **处理 → 反馈 → 学习 → 规则更新**(每一次干预都让 Agent 更懂这位老人) |

> **这八项不是八个功能,而是八种能力** —— 这就是「产品 vs 功能」的本质差异。

## 三、AI Agent 核心架构(显式化 · 七层循环)

> **必须明确:这是一个 Agent,不是一个 AI 监测系统。**

```
                  ┌──────────────────────────────────┐
                  │   Memory Agent(数字老人画像)     │
                  │   Digital Elder Profile           │
                  │   ↑↓ 持续读写                     │
                  └──────────────────────────────────┘
                                ↑↓
        ┌─────────────────────────────────────────────────┐
        │                                                 │
        │   Perceive(感知)         → 风险发现             │
        │        ↓                                        │
        │   Understand(理解)       → 风险证据             │
        │        ↓                                        │
        │   Predict(预测)          → 风险预警(事前)       │
        │        ↓                                        │
        │   Reason(推理)           → 风险解释(可解释)     │
        │        ↓                                        │
        │   Decide(决策)           → 风险干预             │
        │        ↓   Rule + ML + LLM                      │
        │   Act(执行)              → 风险响应             │
        │        ↓   + Trust Enhancement                  │
        │   Learn(学习)            → 风险反馈             │
        │                                                 │
        │        ↓ 回到 Perceive(数字画像持续更新)        │
        └─────────────────────────────────────────────────┘
```

**关键说明**:

- 这 **不是一个分层架构,而是一个 Agent 的核心循环**。
- 每一层都是 Agent 的一个 **能力模块**,有自己的输入、输出、目标。
- **Memory Agent** 不是旁观者,而是 Agent 的「长期记忆」 —— 它维护的数字老人画像,让 Agent 越用越懂这位老人。
- **Learn** 不是离线训练,而是 **每次干预后立即更新规则和画像** —— 这是「持续进化」的本质。

## 六、How(智能层)—— 七层 Agent 详解

> **本人主导。这是 Agent 的核心循环。**

### 6.1 Perceive Agent(感知 · 风险发现)

**目标**:Agent 的眼睛和耳朵。

**输入**:萤石视频流、拾音器、老人手机事件、GPS、门磁。
**输出**:结构化原始事件流。

**关键设计**:
- 全部输出带 `timestamp` + `source`,可追溯。
- 异常信号(掉线、采集失败)必须显式上报。
- 不做判断,只采集事实。

```json
{
  "event_id": "evt_20260630_0915",
  "source": "hikvision_living_room",
  "timestamp": "2026-06-30 09:15:23",
  "type": "visitor_entered"
}
```

---

### 6.2 Understand Agent(理解 · 风险证据)

**目标**:把事实变成证据。

**输入**:Perceive 输出。
**输出**:多模态标签。

```json
{
  "event_id": "evt_20260630_0915",
  "tags": {
    "person":   { "age": "~45", "gender": "male", "uniform": false, "carry": ["宣传袋"] },
    "emotion":  { "elder_stress": 0.83 },
    "speech":   { "keywords": ["投资", "养老金"], "intent": "推销" }
  }
}
```

---

### 6.3 Predict Agent(预测 · 风险预警)

**目标**:预测「未来」,不是判断「已经」。

**输入**:标签 + 历史画像。
**输出**:趋势预测 + 偏离度。

```json
{
  "elder_id": "elder_001",
  "trend":       { "horizon": "next_24h", "rising": true },
  "target_prob": 0.86,
  "deviation":   { "baseline_risk": 0.12, "current_risk": 0.74, "delta": 0.62 }
}
```

**预测范式**:
- **趋势预测**:最近 7 天每天 10+ 陌生电话 → 正在被围猎
- **关系预测**:陌生人连续 7 天上门 → 正在建立信任
- **行为预测**:老人从不参加讲座 → 突然去会销 → 行为强偏离

---

### 6.4 Reason Agent(推理 · 风险解释)

**目标**:给出 **可解释** 的因果链。

**输入**:标签 + 预测 + 数字老人画像。
**输出**:因果链 + 风险来源占比。

```json
{
  "chain": [
    "异地陌生号码呼入",
    "通话持续 42 分钟(异常)",
    "电话含「投资」「养老金」关键词",
    "陌生人连续 3 天上门",
    "老人近期频繁外出(行为偏离)",
    "老人独居(无即时干预能力)"
  ],
  "score_breakdown": {
    "电话信号": 35, "访客信号": 25, "行为偏离": 20,
    "历史趋势": 10, "环境风险": 10
  },
  "confidence": 0.92
}
```

**关键设计**:
- 每条证据可追溯到原始 `source`。
- 这是 Trust 层「可解释预警」的依据来源。

---

### 6.5 Decide Agent(决策 · 风险干预)

**目标**:决定「该不该干预、谁来干预、按什么顺序」。

> **风险引擎三层:RULE + ML + LLM**

```
┌─────────────────────────────────────────────────┐
│  Layer 1 · Rule Engine(毫秒级强信号)           │
│  ──────────────────────────────────────        │
│  验证码 + 银行卡 + 保密 → 直接高危              │
│  陌生号码 + 通话 > 30min → 中危                 │
└─────────────────────────────────────────────────┘
                       ↓ 未命中规则时
┌─────────────────────────────────────────────────┐
│  Layer 2 · ML Model(概率化)                     │
│  ──────────────────────────────────────        │
│  XGBoost / 轻量神经网络                          │
│  输入:多模态标签 + 历史画像                       │
│  输出:风险分数(0-100)+ 异常程度                 │
└─────────────────────────────────────────────────┘
                       ↓ (可选,第二版)
┌─────────────────────────────────────────────────┐
│  Layer 3 · LLM Reasoning(可解释解释)           │
│  ──────────────────────────────────────        │
│  把 ML 数字翻译成「人话」                        │
│  输出:可解释结论 + 干预建议                      │
└─────────────────────────────────────────────────┘
```

**MVP 第一版**:Rule + ML 两层,**LLM Reasoning 暂不做**(第二版加入)。

**关键设计**:
- 规则命中 → 毫秒级触发,**0 误报容忍**。
- ML 输出概率 → 便于阈值调优,可被学习。
- LLM 输出解释 → 让老人/家属/社区读得懂。

---

### 6.6 Act Agent(执行 · 风险响应)

**目标**:把决策真正落到现实。

**输入**:Decide 输出 + Trust 策略。
**输出**:多通道执行 + 反馈日志。

```
Decide → 干预方案
   ↓
Trust 策略注入(可解释 / 认知缓冲 / 第三方验证)
   ↓
多通道协同执行:
  - 本地语音(Home Agent)
  - 微信/App(Family Agent)
  - 短信(异地家属)
  - 社区平台(Community Agent)
  - 录像保存(Memory Agent)
   ↓
执行反馈 → 写入 Memory Agent
```

---

### 6.7 Memory Agent(学习 · 数字老人画像)

**目标**:让 Agent 越来越懂这位老人。

> **这是整个 Agent 的「灵魂中枢」。**

#### 数字老人画像(Digital Elder Profile)结构

```
elder_id: "elder_001"
│
├── 基础档案
│   ├── 人口学:年龄、性别、独居状态
│   └── 居住地:家庭住址、社区、物业
│
├── 长期行为基线(Baseline)
│   ├── 作息:06:00 起夜、08:00 买菜、20:00 看电视
│   ├── 社交:广场舞友、邻居王阿姨
│   ├── 外出:菜市场、广场、社区卫生中心
│   └── 偏好:听戏曲、不喜欢甜食
│
├── 易受骗程度(Vulnerability Score)
│   ├── 静态因素:年龄、教育、收入、独居
│   ├── 动态因素:近期情绪、社交变化、健康
│   └── 历史事件:过去是否被骗过、是否识别过诈骗
│
├── 社交风险地图(Social Risk Map)
│   ├── 高频联系人:女儿、邻居、广场舞友
│   ├── 陌生接触:陌生人来电频率、上门频率
│   └── 异常关系:新建立的陌生关系
│
├── 最近异常事件(Recent Anomalies)
│   ├── 06-23:陌生号码,已忽略
│   ├── 06-26:陌生人上门,家属确认装修
│   └── 06-30:高风险预警,已劝回
│
├── 干预历史(Intervention History)
│   ├── 语音提醒:成功 5 次 / 失败 1 次
│   ├── 家属视频:成功 3 次
│   └── 社区介入:1 次
│
├── 反馈结果(Feedback Results)
│   ├── 30 天误报次数
│   ├── 30 天漏报次数
│   └── 老人信任评分
│
└── 动态风险(Dynamic Risk)
    ├── 当前等级
    ├── 趋势(上升/平稳/下降)
    └── 关键因子
```

#### 画像持续更新机制

| 更新源 | 更新内容 | 频率 |
| --- | --- | --- |
| Perceive Agent | 新事件写入 event_stream | 实时 |
| Understand Agent | 标签更新 | 实时 |
| Predict Agent | 趋势属性 | 实时 |
| Reason Agent | 解释属性 | 实时 |
| Decide Agent | 决策日志 | 实时 |
| Act Agent | 执行反馈 | 实时 |
| 家属反馈 | 误报标记、模式修正 | 事件级 |
| 社区反馈 | 群体模式修正 | 周期级 |
| 自动学习 | ML 权重、白名单、阈值 | 周期级 |

---

### 6.8 持续进化机制(显式化 · 闭环学习)

> **不是「识别结束」,而是「每一次干预都让 Agent 更懂这位老人」。**

```
              干预执行(Act)
                  ↓
            执行反馈(成功/失败)
                  ↓
              家属/社区反馈
              ├─ 误报 → 模式降权 → 阈值上调
              ├─ 漏报 → 模式升权 → 阈值下调
              └─ 成功 → 模式入库 → 画像更新
                  ↓
            ML 模型权重更新
                  ↓
            数字老人画像更新
                  ↓
            下一次判断更精准
                  ↓
              回到 Perceive
```

**三种反馈驱动的学习**:

| 反馈类型 | 触发条件 | 学习动作 |
| --- | --- | --- |
| **误报反馈** | 家属标记「是装修」 | 「陌生人 + 工具袋」模式降权 |
| **漏报反馈** | 老人真的被骗 | 「会销 + 异地电话」模式升权 |
| **成功反馈** | 家属确认「已劝回」 | Trust 策略权重 ↑(如「第三方验证」) |

**这就是 Agent 区别于普通 AI 系统的本质 —— 持续进化**。

## 七、Human(交互层)—— Trust Enhancement(信任增强)

> **由第二位队友主导。这是 Agent 的「人心工程」。**

### 7.1 产品哲学:AI 不是决策者

```
不是:  AI 告诉老人「这是诈骗」 → 老人抗拒
而是:  AI 帮老人找到他愿意相信的人 → 老人接受
```

**具体话术示例**:

| 场景 | ❌ 普通 AI 提醒 | ✅ Agent 信任增强 |
| --- | --- | --- |
| 老人接诈骗电话 | "这是诈骗,请挂断" | "建议联系您的儿子确认一下,系统已为您转接" |
| 老人被推销 | "陌生人有风险" | "社区工作人员已经帮您核验,该活动不存在备案" |
| 老人要转账 | "请勿转账" | "您女儿正在视频通话中,她有话想对您说" |
| 老人被骗后 | "您被骗了" | "这种诈骗套路很常见,我们一起复盘一下,以后您能自己识别" |

### 7.2 Trust 五层机制

#### ① 可解释预警(Explainable Warning)

```
不是:  "危险"
而是:  "检测依据:陌生号码 + 要求转账 + 持续 40 分钟,风险 92%"
```

**为什么有效**:把判断过程「让渡」给老人,信任度立刻上升。

#### ② 认知缓冲(Cognitive Buffer)

```
不是:  "你被骗了"
而是:  "建议您先暂停 5 分钟,系统正在联系您的女儿确认"
```

**为什么有效**:正面对抗触发防御心理,「暂停 5 分钟」是可接受的微小动作。

#### ③ 第三方验证(Third-Party Verification)

```
不是:  "AI 说:这是诈骗"
而是:  "已联系:女儿。她说:妈,千万别转,我 10 分钟到"
```

**为什么有效**:被骗老人对 AI 天然不信任,但 **对家人极度信任**。三段式传递,把 AI 判断转译成老人愿意相信的语言。

#### ④ 长期信任建设(Long-term Bonding)—— 第二版

```
每天:  天气提醒、吃药提醒、喝水提醒、睡眠报告
形式:  像家人,而非像机器
```

#### ⑤ 事后复盘(Post-incident Review)—— 第三版

```
事件:  骗子冒充公安,要求保密、要求转账
复盘:  帮助老人识别「冒充公检法」的套路
成长:  下次再遇到,老人能自己识别 70% 的类似话术
```

### 7.3 MVP 第一版 · Trust 能力

> **MVP 重点:可解释预警 + 第三方验证**(第二版加入长期信任建设,第三版加入事后复盘)

| 能力 | 第一版 | 第二版 | 第三版 |
| --- | --- | --- | --- |
| 可解释预警 | ✅(ML 分数 + 关键证据) | ✅ + LLM 解释 | ✅ |
| 认知缓冲 | ✅(默认话术) | ✅ | ✅ |
| 第三方验证 | ✅(转接家属视频) | ✅ | ✅ |
| 长期信任建设 | ❌ | ✅ | ✅ |
| 事后复盘 | ❌ | ❌ | ✅ |

## 十一、答辩统一表述(完整版 · 可直接复用)

> 我们构建的不是一个反诈 AI 功能,而是一个 **反诈 Agent(银龄盾 · Elder Fraud Agent)**。
>
> 这个 Agent 拥有 **七层循环感知与推理能力**(Perceive→Understand→Predict→Reason→Decide→Act→Learn)、**一份长期维护的数字老人画像(Digital Elder Profile)**、**一条反馈驱动的持续进化闭环**,并在 **老人-家属-社区** 三方之间充当 **信任的桥梁**。
>
> 我们的产品哲学是:**AI 不是决策者,而是「帮助老人相信正确的人」**。Agent 不直接告诉老人「这是诈骗」,而是通过 **可解释预警、第三方验证、长期陪伴**,帮老人找到他愿意相信的那个人,让那个人来传达判断。
>
> 系统部署在 **Home + Mobile + Family + Community** 四端,由 **四个分布式 Agent** 自治协同,在 **家里、家门外、家属身边、社区网格** 中,同步识别、分级响应。
>
> 风险引擎采用 **Rule + ML + LLM 三层决策架构**(MVP 第一版实现 Rule + ML 两层),兼顾 **毫秒级响应、概率化输出、可解释结论**。
>
> 我们的核心壁垒不是某个模型,而是 **三种长期资产**:每位老人独立的 **Digital Elder Profile**、反馈驱动的 **持续学习闭环**、通过长期陪伴建立的 **Trust 信任**。这三件事,竞品难以复制。
>
> 第一版我们没有做 AI 换脸、AI 拟声、通用 LLM 对话,因为两个月做不完。**第一版我们只做一件事:让一个独居老人,在被骗之前 30 分钟,被家属或社区拦下来**。
>
> 这不是一个比赛作品,而是一个 **数字守护 Agent 平台** —— 用一个持续进化的 Agent,守护每一位独居老人。
