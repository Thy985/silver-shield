# AI Risk Agent · 九层架构(三位一体融合版)

> **项目定位**
> 我们并不是开发一个简单的防诈骗识别系统,而是构建一个面向居家养老场景的 **AI 风险智能体(AI Risk Agent)**。
> 系统以萤石开放平台为感知基础,融合视频、音频、行为和环境等多模态信息,通过 **「感知—理解—预测—推理—评估—资源规划—执行—信任增强—持续学习」** 的完整智能闭环,实现从传统事后报警向 **事前风险预警、智能干预和持续学习** 的升级。
> 同时,我们特别关注老年人在深度情感操控下对技术预警的不信任问题,引入 **可解释预警、第三方验证、长期信任建设** 机制,使 AI 不仅能够识别诈骗,更能够让老人 **愿意接受帮助**,真正完成风险防控的最后一公里。

---

## 一、为什么是「九层」而不是「大模型一把梭」

把整套逻辑塞进一个 LLM,会出现三个致命问题:

1. **事实与判断混淆**:模型既采集事实,又下结论,无法审计。
2. **上下文爆炸**:摄像头、手机、GPS、门磁、家时反馈同时涌入,推理能力迅速衰减。
3. **信任崩塌**:一个黑盒说「你被骗了」,老人大概率不会听。

**分层原则**:

- 每一层都有明确的 **输入、输出、职责边界**。
- 上层只依赖下层的结构化输出,不直接消费原始信号。
- 每一层都可被 **独立替换、独立训练、独立评估**。
- 防诈骗真正难的不是「识别」,而是「让老人相信」—— 因此把 **Trust(信任增强)** 单列一层,与执行并列,而不是塞进 Act。

## 二、九层架构总览

```
                         AI Risk Agent
──────────────────────────────────────────────────────────────

  Perceive(感知)        → 世界发生了什么?(事实)
        ↓
  Understand(理解)      → 这些事实意味着什么?(标签)
        ↓
  Predict(预测)         → 未来风险趋势(事前预警)
        ↓
  Reason(推理)          → 综合因果链,给出可解释结论
        ↓
  Evaluate(风险评估)    → 风险有多大?为什么?
        ↓
  Plan(资源规划)        → 谁最适合介入?按什么顺序?
        ↓
  Act(执行干预)         → 语音 / 微信 / 短信 / 录像 / 应急流程
        ↓
  Trust(信任增强)       → 让老人愿意接受帮助
        ↓
  Learn(持续学习)       → 闭环反馈、画像更新、规则迭代
        ↓
  → 回到 Perceive(闭环)
```

**核心新增**:相比普通 Agent 多出两层 ——

- **Evaluate(风险评估)**:把「有没有诈骗」升级为「危险到什么程度 + 各项贡献度」。
- **Trust(信任增强)**:把「AI 说了」升级为「老人愿意相信」—— 这是防诈骗区别于其他 AI 应用的 **真正护城河**。

## 三、三位一体:三套思路如何融合为一个 Agent

> **关键认知**:三套思路不是互相竞争,而是 **三个层级** —— 产品层、智能层、交互层,共同构成一个完整的 AI Risk Agent。

| 层级 | 负责人 | 贡献内容 | 对应架构层 |
| --- | --- | --- | --- |
| **产品层** | 第一位队友 | 场景覆盖、系统架构、业务流程、多模态接入、萤石平台 | Perceive / Understand(事实与标签) |
| **智能层** | 本人(AI Risk Agent) | 感知 → 理解 → 预测 → 推理 → 评估 → 规划 → 学习 | Perceive / Understand / Predict / Reason / Evaluate / Plan / Act / Learn |
| **交互层** | 第二位队友 | 信任机制、认知对抗、可解释 AI、人机协同、行为干预 | Trust / 嵌入 Act 的对话设计 |

**融合后的统一逻辑**:

```
                业务场景与多模态感知
              (产品层 · 第一位队友)
                       ↓
              ┌────────────────────┐
              │   AI Risk Agent    │
              │                    │
              │  Perceive          │
              │     ↓              │
              │  Understand        │
              │     ↓              │
              │  Predict           │
              │     ↓              │
              │  Reason            │  ← 智能层
              │     ↓              │     (核心团队)
              │  Evaluate          │
              │     ↓              │
              │  Plan              │
              │     ↓              │
              │  Act               │
              │     ↓              │
              │  Trust  ← 交互层   │  ← 交互层
              │     ↓              │     (第二位队友)
              │  Learn            │
              └────────────────────┘
                       ↓
                  持续学习闭环
```

**为什么这样融合**:

- **产品层提供「输入的真实性」** —— 没有萤石平台与多模态感知,后面所有智能都是空中楼阁。
- **智能层提供「判断的准确性」** —— 风险识别、资源调度,都依赖中间的 7 层核心。
- **交互层提供「干预的有效性」** —— 再准的判断,老人不信也无效;Trust 层让识别真正转化为「老人愿意接受的帮助」。

**三位一体 = 真实输入 + 准确判断 + 有效干预**,这才是项目真正完整的地方。

## 四、各层详解

### 4.1 Perceive(感知)

**目标**:世界发生了什么?

**铁律**:这一层 **不能思考**,只能采集事实。输出中禁止出现「诈骗」「危险」「骗子」等判断词。

**融合产品层(第一位队友)的多模态感知**:

| 模态 | 数据源 | 采集内容 |
| --- | --- | --- |
| **视频** | 萤石摄像头、门铃 | 陌生人识别、访客停留、老人动作、人体行为 |
| **音频** | 拾音器、电话监听 | 环境对话、关键词、AI 拟声检测、电话内容 |
| **手机** | 手机 Agent(权限范围内) | 陌生号码、安装未知 App、短信、浏览器访问 |
| **环境** | 时钟、GPS、门磁 | 时间、地点、是否独居、是否夜间、是否连续来访 |

**输出示例**:

```json
[
  { "time": "09:32", "event": "陌生号码呼入",   "duration": 38 },
  { "time": "10:15", "event": "陌生男子进入",   "stay": 42 },
  { "time": "10:18", "event": "老人情绪紧张",   "source": "audio_emotion" }
]
```

**设计要点**:
- 全部输出必须带 `timestamp` 与 `source`,便于上层溯源。
- 异常信号(掉线、采集失败)必须显式上报,**不可静默丢弃**。
- 「老人情绪紧张」这类信号来自音频情绪识别,但这里 **只输出事实**,不解读含义。

---

### 4.2 Understand(理解)

**目标**:这些事实意味着什么?

**职责**:把原始事实 **标签化、结构化**。

| 输入事实 | 输出标签 |
| --- | --- |
| 陌生号码 | 运营商未知 / 第一次联系 / 高频骚扰地区 |
| 陌生人进入 | 未登记访客 / 携带宣传资料 / 连续三天到访 |
| 电话内容(语音转写) | 涉及「安全账户」「保密」「投资」「养老金」 |

**输出示例**:

```json
{
  "call":   { "carrier": "unknown", "history": "first_contact", "region": "高频骚扰地" },
  "visitor":{ "registered": false, "carry": ["宣传资料"], "frequency": "3天连续" },
  "speech": { "keywords": ["安全账户", "保密", "投资", "养老金"] }
}
```

**铁律**:**仍然不说「诈骗」**。只是把事实映射到可计算的标签空间。

**设计要点**:
- 这一层是 **CV/NLP/语音模型的主战场**,但只输出标签,不下结论。
- 标签体系必须 **可枚举、可版本管理**,便于 `Learn` 层做权重更新。

---

### 4.3 Predict(预测)

**目标**:未来是否存在风险?

**这是比赛最关键的一层** —— 比赛要求的是 **事前预警**,不是「已经被骗」。

**预测范式**(三条并行):

1. **趋势预测**:最近每天接十几个陌生电话 → **正在被诈骗团伙围猎**。
2. **关系预测**:陌生人连续一周上门 → **可能正在建立长期信任关系**。
3. **行为预测**:老人最近频繁去保健品讲座 → **未来被骗风险增加**。

**输出示例**:

```json
{
  "trend":       "rising",
  "horizon":     "next_24h",
  "target_prob": 0.86,
  "deviation":   "high",
  "predicted_type": "投资/养老诈骗"
}
```

**铁律**:这一层 **不是判断「有没有被骗」**,而是预测 **「未来」**。

**设计要点**:
- 必须有时间窗口(近 7 天 / 24 小时 / 实时)。
- 输出要有 **不确定性**(`confidence`),便于上层 Reason 做加权。
- 这层模型可以 **离线跑批**,不要求实时。

---

### 4.4 Reason(推理)

**目标**:把多源证据串成因果链,得出 **可解释** 的综合风险评分。

**为什么不能是黑盒**:
- 老人不会信「系统说 90 分」,但会信「系统说出了 6 条理由」。
- 家属和社区需要 **可审计** 的依据,才能介入。

**推理示例**:

```
Q: 为什么风险 90?
A: 因为同时满足
   ① 陌生号码(异地)
   ② 40 分钟电话(异常时长)
   ③ 涉及「投资」「养老金」关键词
   ④ 陌生人拜访(连续 3 天)
   ⑤ 老人近期行为异常(频繁外出)
   ⑥ 老人独居(无即时干预能力)
```

**输出示例**:

```json
{
  "risk_score": 90,
  "sources": {
    "电话":      { "contribution": 35, "evidence": ["异地号码", "40min", "投资关键词"] },
    "行为":      { "contribution": 20, "evidence": ["近期频繁外出"] },
    "访客":      { "contribution": 25, "evidence": ["陌生人连续 3 天"] },
    "历史趋势":  { "contribution": 10, "evidence": ["首次出现此模式"] },
    "环境风险":  { "contribution": 10, "evidence": ["独居"] }
  },
  "confidence": 0.92
}
```

**设计要点**:
- 这一层真正体现 **Agent 思维** —— 多步推理、可回溯。
- 每条证据必须能追溯到原始 `source`(摄像头 ID、通话 ID)。
- 这是 **Trust 层「可解释预警」** 的依据来源。

---

### 4.5 Evaluate(风险评估)

**目标**:风险有多大?**为什么?**

> 这是你一直强调的关键问题 —— 不是「有没有诈骗」,而是「到底危险到什么程度」。

**输出维度**:

| 维度 | 说明 | 示例 |
| --- | --- | --- |
| **等级** | 数值化(0–100)或分档 | `score: 92, level: 极高` |
| **类型** | 当前最可能的风险类别 | `type: 投资诈骗` |
| **紧迫度** | 时间窗口 | `urgency: 30min` |
| **风险来源占比** | 各因素贡献度(承接 Reason 层输出) | 投资诈骗 55% / 陌生人 25% / 行为异常 20% |
| **置信度** | 评估本身的可信度 | `confidence: 0.92` |
| **一句话解释** | 给家属/社区/老人看 | "老人正在被陌生电话引导至投资诈骗,行为模式已发生明显偏离" |

**输出示例**:

```json
{
  "score": 92,
  "level": "极高",
  "type": "投资诈骗",
  "urgency": "30min",
  "breakdown": {
    "投资诈骗": 55,
    "陌生人":   25,
    "行为异常": 20
  },
  "confidence": 0.92,
  "explanation": "陌生异地号码引导投资 + 频繁外出行为偏离 + 独居无人即时干预"
}
```

**铁律**:**只评估,不调度**。不知道、不关心「找谁」。

**设计要点**:
- 阈值划分要 **可配置**,不同老人、不同地区可调。
- 必须给出 **可解释的输出** —— 这是家属信任度的关键。
- 对应第二位队友的「**透明预警**」需求。

---

### 4.6 Plan(资源规划)

**目标**:谁最适合介入?按什么顺序?

> 这是整个项目 **最大的升级点** —— 普通识别系统只能告诉你「风险高」,这里能告诉你「**谁去救**」。

**资源池与决策规则**:

| 场景 | 资源选择 | 原因 |
| --- | --- | --- |
| 家属就在附近 | **家属**(一级) | 信任度最高、响应最快 |
| 家属在国外 | **社区**(一级) + 邻居(二级) | 家属远水难救近火,本地资源优先 |
| 老人正在转账 | **警方**(直接介入) | 资金紧急,需要执法力量 |
| 陌生人敲门(轻风险) | **门铃语音提醒**(一级) | 不升级打扰,但阻止陌生人 |
| 跌倒/生命危险 | **邻居 + 120**(一级) | 比家属到场更快 |

**规划维度**:

| 维度 | 说明 |
| --- | --- |
| **可达性** | 资源当前是否可用?(家属是否在上班、邻居是否在家) |
| **距离/响应时间** | 邻居 3 分钟 vs 异地家属 2 小时 |
| **能力匹配** | 跌倒 → 急救;诈骗 → 家属或社区;暴力 → 警方 |
| **信任度** | 老人与该资源的历史信任关系(承接 Trust 层) |
| **成本** | 误报社会成本(打扰家属次数、社区资源占用) |
| **顺序** | 先本地快响应,再异地慢响应,最后升级 |

**输出示例**:

```json
{
  "primary":    { "resource": "邻居-王阿姨",   "ETA": "3min", "action": "上门确认" },
  "secondary":  { "resource": "家属-女儿",     "ETA": "12min(可视频)", "action": "远程视频确认" },
  "tertiary":   { "resource": "社区网格员",    "ETA": "30min", "action": "待命,前两级无响应则升级" },
  "fallback":   { "resource": "派出所",        "ETA": "45min", "action": "转账行为触发" },
  "self_action": ["客厅音箱语音提醒", "保存最近 30min 录像"]
}
```

**典型案例对比**:

| 场景 | 风险相同? | 最佳资源 |
| --- | --- | --- |
| **老人家中疑似跌倒** | 高 | **最近邻居 / 120**,而非远在外地的家属 |
| **接到疑似诈骗电话** | 高 | **先弹本地语音提醒 → 再联系家属**,而非直接通知社区 |
| **疑似会销现场被困** | 高 | **家属 + 物业双线**(物业可立即上门,家属可远程视频) |
| **独居老人失联 24h** | 中→高 | **物业 + 社区网格员**,物业先敲门,网格员同步上门 |

**设计要点**:
- 这是系统的 **核心护城河** —— 普通识别系统只能告诉你「风险高」,而这里能告诉你「**谁去救**」。
- 资源池必须 **动态感知**(家属是否在线、邻居是否响应过、社区是否值班)。
- 顺序必须 **可解释**,方便事后审计。

---

### 4.7 Act(执行干预)

**目标**:把 `Plan` 的指令真正落到现实。

**执行通道与内容**:

| 通道 | 适用对象 | 典型内容 |
| --- | --- | --- |
| **本地语音** | 老人 | "爸,请暂停操作,您的女儿正在视频确认" |
| **微信/App** | 家属 | "诈骗风险 92%,建议立即视频确认" |
| **短信** | 异地家属 | "老人连续三天遭遇陌生人拜访,建议联系" |
| **社区平台** | 网格员 | "老人疑似被围猎,需要上门确认" |
| **110/派出所** | 警方 | 自动生成事件报告 |
| **录像/证据** | 事后追溯 | 保存关键片段 |

**铁律**:
- **可逆操作优先**(语音提醒可放给所有家属,但「直接报警」必须经过人工确认)。
- 每次执行必须带 **事件 ID**,便于 `Learn` 回溯。
- 不是「简单推送」,而是 **多通道协同的执行干预**。

---

### 4.8 Trust(信任增强)—— 整个项目的真正护城河

**为什么单独成层**:
> 防诈骗真正难的不是识别,而是 **让老人相信**。
> 老人被骗的核心是 **深度情感操控**,他们对「陌生人」反而建立了信任,对「AI 提醒」反而抗拒。
> 因此,Trust 不是 Act 的附属,而是与 Act **并列的独立一层**。

**建议拆成五层机制**(对应第二位队友的贡献):

#### ① 可解释预警(Explainable Warning)

```
不是:  "危险"
而是:  "检测依据:陌生号码 + 要求转账 + 持续 40 分钟,风险 92%"
```

**为什么有效**:老人抗拒的不是「危险」本身,而是 **「莫名其妙的断言」**。把依据摆出来,等于把判断过程「让渡」给老人,信任度立刻上升。

#### ② 认知缓冲(Cognitive Buffer)

```
不是:  "你被骗了"
而是:  "建议您先暂停 5 分钟,系统正在联系您的女儿确认"
```

**为什么有效**:正面对抗(「你被骗了」)会让老人立刻站到骗子一边(「你们都不了解我」)。
**「暂停 5 分钟」** 是一个微小的、可接受的动作,不会触发防御心理,但能为真正的干预争取时间。

#### ③ 第三方验证(Third-Party Verification)

```
不是:  "AI 说:这是诈骗"
而是:  "已联系:女儿。她说:妈,千万别转,我 10 分钟到"
```

**为什么有效**:被骗的老人对 AI 系统天然不信任,但 **对家人极度信任**。
通过「AI → 家属 → 老人」的三段式传递,把 AI 的判断 **转译** 成老人愿意相信的语言。

#### ④ 长期信任建设(Long-term Bonding)

```
每天:  天气提醒
       吃药提醒
       喝水提醒
       睡眠报告

形式:  像家人,而非像机器
```

**为什么有效**:信任不是危机时刻才建立的,而是 **日常 365 天慢慢攒出来的**。
当 AI 一直以「关心者」而非「警告者」的形象出现,危机时刻的提醒才有分量。

#### ⑤ 事后复盘(Post-incident Review)

```
事件:  骗子冒充公安,要求保密、要求转账
复盘:  帮助老人识别「冒充公检法」的套路
成长:  下次再遇到,老人能自己识别 70% 的类似话术
```

**为什么有效**:被骗后的复盘不是揭伤疤,而是 **把一次伤害转化为长期免疫力**。
配合家属一起做,还能修复老人被诈骗损伤的自我价值感。

**Trust 层与 Act 层的关系**:

| 层 | 职责 | 类比 |
| --- | --- | --- |
| **Act** | 把决策 **执行出去**(对谁说、说什么、怎么发) | 战术动作 |
| **Trust** | 让决策 **被接受**(为什么信、愿不愿意听、长期关系) | 战略能力 |

**没有 Trust 的 Act**:发了一百条提醒,老人全部忽略。
**有 Trust 的 Act**:一句话,老人立刻停下转账操作。

### 4.9 Learn(持续学习)

**目标**:让系统越来越懂这位老人。

**反馈通道**:

1. **家属反馈**:「其实是装修,不是骗子」→ 降低「陌生男性 + 长时间停留」权重。
2. **误报修正**:同一模式 5 次都被否定 → 该模式降权。
3. **漏报学习**:未被识别的诈骗 → 该模式升权,补充进训练集。
4. **画像更新**:老人近期作息、社交圈、偏好地点持续更新。
5. **规则迭代**:风险评分公式、阈值、Plan 顺序都被纳入迭代。

**示例闭环**:

```
AI 报警:陌生人停留 40 分钟
   ↓
家属反馈:其实是装修
   ↓
Learn 层:
   1. 「装修」模式入库
   2. 「装修师傅 + 工具袋」标签 → 风险降权
   3. 下次类似场景 → 不再触发高分预警
```

```
AI 未报警
   ↓
老人被骗
   ↓
Learn 层:
   1. 「保健品会销」模式升权
   2. 「陌生电话 30min+」+ 「异地 GPS」组合 → 权重 ↑
   3. 下次类似场景 → 提前至 Evaluate 阶段触发高分
```

**设计要点**:
- 反馈必须 **轻量化** —— 家属只需「是/否」一键,否则不会填。
- 画像按 **个人粒度** —— 系统越用越懂「**这位**老人」。
- Trust 层的「长期信任建设」本身就是 Learn 的 **数据源**:每天的天气、吃药、喝水提醒,既建立信任,又采集老人最新作息基线。

## 七、典型场景全链路演示

### 场景 1:保健品/投资诈骗(事前预警)

```
09:32  Perceive   摄像头:陌生人进入,无物业制服,拿宣传袋
09:32  Perceive   手机:陌生异地号码呼入
10:15  Perceive   GPS:老人离家 → 某酒店(会销高发地)
10:18  Perceive   音频:老人情绪紧张

10:16  Understand 人:45 岁男性,无制服,携带宣传资料
       Understand 通信:异地号码,运营商未知,无历史联系
       Understand 地点:会销高发地

10:17  Predict    趋势:过去 7 天连续参加 3 次免费活动
                  偏离:从不参加讲座 → 今天去会销
                  → 未来 24h 风险上升

10:18  Reason     链:陌生电话(异地)+ 42min + 投资关键词
                  + 陌生人连续 3 天 + 独居
                  → risk_score: 92

10:19  Evaluate   level: 极高, type: 投资诈骗
                  紧迫度:30min, 置信度:0.92
                  breakdown: 投资 55% / 陌生人 25% / 行为 20%

10:19  Plan       primary:   邻居(3min,上门确认)
                  secondary: 家属-女儿(12min,视频通话)
                  tertiary:  物业(20min,可拦截)
                  fallback:  社区网格员(30min)
                  self:      客厅音箱语音提醒 + 保存录像

10:20  Act        播放语音「爸,有什么事等我回家再说」
                  推送女儿微信 → 报警警情 92%
                  保存录像

10:20  Trust      【可解释预警】"检测依据:异地陌生号码 + 要求转账 + 40min"
                  【认知缓冲】"建议您先暂停 5 分钟,女儿正在路上"
                  【第三方验证】"已联系女儿,她说 10 分钟到"
                  (避免直接说"你被骗了")

10:50  Act        老人返回,女儿已视频确认 → 邻居/物业撤出

11:00  Learn      家属反馈:已劝回
                  模式入库:「异地电话 + 会销酒店」权重 ↑
                  Trust 记录:本次「第三方验证」成功 → 该策略权重 ↑
```

### 场景 2:老人家中疑似跌倒

```
06:30  Perceive   摄像头:客厅长时间无人活动
06:30  Perceive   门磁:大门未开(老人未外出)
06:30  Perceive   GPS:信号弱 → 推断仍在室内
06:32  Reason     偏离:老人通常 06:00 起夜,06:30 仍未见活动

06:32  Evaluate   level: 中高, type: 跌倒/晕厥
                  紧迫度:15min

06:32  Plan       primary:   邻居-王阿姨(3min,敲门确认)  ← 不是家属!
                  secondary:  120(若邻居 5min 无响应)
                  fallback:   家属-女儿(异地,信息同步)

06:35  Act        邻居到场 → 确认跌倒 → 已叫 120 → 通知女儿

06:36  Trust      【认知缓冲】"王阿姨来敲门,问问您要不要去医院"
                  (而非"您可能摔倒了"——避免惊吓)

06:55  Learn      画像:老人 06:00–07:00 卫生间使用频率高
                  → 下次类似偏离,降低「跌倒」权重
                  Trust 记录:本次「第三方验证」成功 → 王阿姨信任度 ↑
```

**关键差异**:
- 同样是高风险事件,**诈骗场景**的最佳资源是「家属 + 远程介入」。
- **跌倒场景**的最佳资源是「邻居 + 急救」,而不是远在外地的家属。

这就是 `Plan` 层的价值。

## 八、答辩统一表述(可直接复用)

> 我们并不是开发一个简单的防诈骗识别系统,而是构建一个面向居家养老场景的 **AI 风险智能体(AI Risk Agent)**。
>
> 系统以萤石开放平台为感知基础,融合视频、音频、行为和环境等多模态信息,通过 **「感知—理解—预测—推理—评估—资源规划—执行—信任增强—持续学习」** 的完整智能闭环,实现从传统事后报警向 **事前风险预警、智能干预和持续学习** 的升级。
>
> 同时,我们特别关注老年人在深度情感操控下对技术预警的不信任问题,引入 **可解释预警、第三方验证、长期信任建设** 机制,使 AI 不仅能够识别诈骗,更能够让老人 **愿意接受帮助**,真正完成风险防控的最后一公里。

## 九、总结

**九层架构的本质**,是把三个独立的思路,合成一条 **可审计、可解释、可调度、可被信任** 的工程流水线。

- **第一位队友**(产品层)负责 **真实输入** —— 没有萤石平台与多模态感知,后面所有智能都是空中楼阁。
- **智能层**(本人)负责 **准确判断 + 资源调度** —— 风险识别不是终点,「谁去救」才是终点。
- **第二位队友**(交互层)负责 **有效干预** —— 再准的判断,老人不信也无效。

**三位一体 = 真实输入 + 准确判断 + 有效干预**。

识别、决策、资源调度、信任建立和持续学习,都服务于 **「帮助老人避免损失」** 这一个核心目标 —— 这就是项目真正完整、真正创新、真正符合评委对「系统完整性与创新性」期待的地方。

> `Perceive → Understand → Predict → Reason → Evaluate → Plan → Act → Trust → Learn → 回到 Perceive`
