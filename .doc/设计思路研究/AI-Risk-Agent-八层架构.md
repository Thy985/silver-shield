# AI Risk Agent · 八层架构

> **核心定位升级**:从「AI 识别风险」到「AI 调度最优资源」——
> 这不仅是一个识别系统,更是一个 **风险决策与资源调度系统**。

---

## 一、为什么需要八层架构(而非一个大模型)

把整套逻辑塞进一个 LLM,会出现三个致命问题:

1. **事实与判断混淆**:模型既采集事实,又下结论,无法审计。
2. **上下文爆炸**:摄像头、手机、GPS、门磁、家属反馈同时涌入,模型推理能力迅速衰减。
3. **决策黑箱**:出问题时无法定位是哪一层失灵。

**分层原则**:
- **每一层都有明确的输入、输出、职责边界。**
- **上层只依赖下层的结构化输出,不直接消费原始信号。**
- **每一层都可被独立替换、独立训练、独立评估。**

---

## 二、八层架构总览

```
┌────────────────────────────────────────────────────────┐
│   Perceive(感知)         → 采集事实                    │
│            ↓                                            │
│   Understand(理解)       → 标签化、结构化               │
│            ↓                                            │
│   Predict(预测)          → 风险趋势研判                 │
│            ↓                                            │
│   Reason(推理)           → 综合计算风险评分             │
│            ↓                                            │
│   Evaluate(风险评估)     → 风险有多大、为什么           │
│            ↓                                            │
│   Plan(资源规划)         → 谁最适合介入、按什么顺序     │
│            ↓                                            │
│   Act(执行)              → 语音/微信/短信/录像/机器人   │
│            ↓                                            │
│   Learn(学习)            → 反馈闭环、画像更新           │
└────────────────────────────────────────────────────────┘
```

**关键拆分**:原 `Decide(决策)` 被拆成两层 ——

- `Evaluate` 回答:**「风险有多大?为什么?」**
- `Plan` 回答:**「谁最适合介入?家属?社区?邻居?警方?」**

这一拆分,让系统从「会识别」升级到「会调度」。

---

## 三、各层详解

### 3.1 Perceive(感知)

**目标**:世界发生了什么?

**铁律**:这一层 **不能思考**,只能采集事实。输出中禁止出现「诈骗」「危险」「骗子」等判断词。

**数据源**:

| 数据源 | 采集方式 | 输出示例 |
| --- | --- | --- |
| 萤石摄像头 | RTSP / 云端事件流 | `{time, event, location}` |
| 手机 Agent | 通话记录 / 应用事件 | `{caller, duration}` |
| GPS | 定位上报 | `{location, timestamp}` |
| 门铃 | 触发事件 + 抓拍 | `{visitor, ring_time}` |
| 门磁 | 开合状态 | `{door, state}` |
| 家属反馈 | 微信/小程序 | `{feedback, content}` |

**示例**:

```json
// 摄像头
{
  "time": "09:20",
  "event": "陌生人进入",
  "location": "客厅"
}

// 手机 Agent
{
  "caller": "陌生号码",
  "duration": 42
}

// GPS
{
  "location": "XX酒店",
  "timestamp": "10:15"
}
```

**设计要点**:
- 全部输出必须带 `timestamp` 与 `source`,便于上层溯源。
- 异常信号(掉线、采集失败)必须显式上报,**不可静默丢弃**。

---

### 3.2 Understand(理解)

**目标**:这些事实意味着什么?

**职责**:把原始事实 **标签化、结构化**。例如:

| 输入事实 | 输出标签 |
| --- | --- |
| 摄像头抓拍:陌生男性 | `{age: ~45, gender: male, uniform: false, carry: 宣传袋, talking: true}` |
| 手机:陌生号码 | `{region: 异地, history: 无联系, carrier_tag: 未知}` |
| GPS:某酒店 | `{venue_type: 保健品会销高发地点}` |

**铁律**:**仍然不说「诈骗」**。只是把事实映射到一个可计算的标签空间。

**输出示例**:

```json
{
  "person": { "age": 45, "gender": "male", "uniform": false, "carry": ["宣传袋"] },
  "call":   { "region": "异地", "duration": 42, "history": "无联系" },
  "venue":  { "type": "会销高发地", "risk_tag": "high_freq_fraud" }
}
```

**设计要点**:
- 这一层是 **CV/NLP/语音模型的主战场**,但只输出标签,不下结论。
- 标签体系必须可枚举、可版本管理,便于后续 `Learn` 层做权重更新。

---

### 3.3 Predict(预测)

**目标**:未来是否存在风险?

**这是比赛最关键的一层**——比赛要求的是 **事前预警**,不是「已经被骗」。

**预测范式**(三条并行):

1. **趋势预测**:过去 7 天,老人连续参加三个免费活动 → 风险正在升高。
2. **目标概率**:最近连续收到 5 个陌生电话 → 成为诈骗目标的概率增加。
3. **行为偏离**:老人以前从不参加讲座,今天突然去保健品会销 → 强偏离信号。

**输出示例**:

```json
{
  "trend":       "rising",
  "target_prob": 0.73,
  "deviation":   "high",
  "horizon":     "next_24h"
}
```

**设计要点**:
- 必须有时间窗口(近 7 天/24 小时/实时)。
- 输出要有 **不确定性**(`confidence`),便于上层 Reason 做加权。
- 这层模型可以 **离线跑批**,不要求实时。

---

### 3.4 Reason(推理)

**目标**:把多源证据串成因果链,得出综合风险评分。

**推理范式**(链式因果):

```
陌生电话
   ↓ 持续 42 分钟
   ↓
老人离开家
   ↓
进入会销高发酒店
   ↓
陌生人持续陪同
   ↓
老人拿出银行卡
   ↓
准备出门
   ↓
→ 风险:上升
```

**与 Understand 的区别**:
- Understand 给的是 **单点标签**(人、号码、地点)。
- Reason 给的是 **跨源因果链** —— 多点标签之间的逻辑关系。

**输出示例**:

```json
{
  "risk_score": 72,
  "chain": [
    "陌生电话 → 异地号码",
    "通话 42 分钟 → 异常时长",
    "老人离家 → GPS 至会销酒店",
    "陌生人持续陪同 → 高度可疑"
  ],
  "evidence": ["cam_0912", "call_0935", "gps_1015"]
}
```

**设计要点**:
- 这一层真正体现 **Agent 思维** —— 多步推理、可回溯。
- 每条证据必须能追溯到原始 `source`(摄像头 ID、记录 ID)。

---

### 3.5 Evaluate(风险评估)

**目标**:风险有多大?**为什么?**

> 这是从原 `Decide` 拆分出来的第一层,只负责 **度量风险**,不负责「找谁来帮忙」。

**输出维度**:

| 维度 | 说明 | 示例 |
| --- | --- | --- |
| **等级** | 数值化(0–100)或分档(低/中/高/极高) | `score: 78, level: high` |
| **类型** | 当前最可能的风险类别 | `type: 保健品会销诈骗` |
| **紧迫度** | 时间窗口 | `urgency: 30_min` |
| **关键证据** | 支撑结论的 Top 3 证据 | `["陌生号码 42 分钟", "会销酒店"]` |
| **置信度** | 评估本身的可信度 | `confidence: 0.82` |
| **解释** | 给家属/社区看的一句话 | `"陌生来电后,老人前往高风险地点并由陌生人陪同,符合会销诈骗早期模式"` |

**铁律**:**只评估,不调度**。不知道、不关心「找谁」。

**设计要点**:
- 阈值划分要支持 **可配置**,不同老人、不同地区可调。
- 必须给出 **可解释的输出** —— 这是后续家属信任度的关键。

---

### 3.6 Plan(资源规划)

**目标**:谁最适合介入?按什么顺序?

> 这是从原 `Decide` 拆分出来的第二层,也是整个项目 **最具差异化、最容易与普通识别系统拉开差距的一层**。

**资源池**:

```
┌─────────────────────────────────────────────┐
│  家属(本地/异地)                              │
│  邻居(距离 ≤ 500m)                           │
│  物业(签约小区)                              │
│  社区网格员(归属街道)                        │
│  派出所(高危案事件)                          │
│  急救(120,仅跌倒/医疗)                       │
│  AI 自身(语音提醒、短信、App Push)            │
└─────────────────────────────────────────────┘
```

**规划维度**:

| 维度 | 说明 |
| --- | --- |
| **可达性** | 资源当前是否可用?家属是否在上班?邻居是否在家? |
| **距离/响应时间** | 邻居 3 分钟 vs 外地家属 2 小时 |
| **能力匹配** | 跌倒→急救;诈骗→家属或社区;暴力→警方 |
| **信任度** | 老人与该资源的历史信任关系 |
| **成本** | 误报社会成本(打扰家属次数、社区资源占用) |
| **顺序** | 先本地快响应(邻居/物业),再异地慢响应(家属),最后升级(社区/警方) |

**典型案例对比**:

| 场景 | 风险相同? | 最佳资源 |
| --- | --- | --- |
| **老人家中疑似跌倒** | 高 | **最近邻居 / 120**,而非远在外地的家属 |
| **接到疑似诈骗电话** | 高 | **先弹本地语音提醒 → 再联系家属**,而非直接通知社区 |
| **疑似会销现场被困** | 高 | **家属 + 物业双线**(物业可立即上门,家属可远程视频) |
| **独居老人失联 24h** | 中→高 | **物业 + 社区网格员**,物业先敲门,网格员同步上门 |

**输出示例**:

```json
{
  "primary":    { "resource": "邻居-王阿姨",   "ETA": "3min", "action": "上门确认" },
  "secondary":  { "resource": "家属-女儿",     "ETA": "12min(可视频)", "action": "远程视频确认" },
  "tertiary":   { "resource": "社区网格员",    "ETA": "30min", "action": "待命,前两级无响应则升级" },
  "fallback":   { "resource": "派出所",        "ETA": "45min", "action": "失联超过 1h 触发" },
  "self_action": ["播放语音提醒", "保存最近 30min 录像"]
}
```

**设计要点**:
- 这是系统的 **核心护城河** —— 普通识别系统只能告诉你「风险高」,而这里能告诉你「**谁去救**」。
- 资源池必须 **动态感知**(家属是否在线、邻居是否响应过、社区是否值班)。
- 顺序必须可解释,方便事后审计。

---

### 3.7 Act(执行)

**目标**:把 `Plan` 的指令真正落到现实。

**执行通道**:

| 通道 | 适用场景 | 优先级 |
| --- | --- | --- |
| **本地语音提醒** | 老人身边,需立即阻止 | 最高 |
| **App Push / 微信** | 家属、社区 | 高 |
| **短信** | 异地家属、无 App 场景 | 中 |
| **录像/证据保存** | 事后追溯 | 自动 |
| **应急流程触发** | 跌倒、暴力、生命危险 | 最高 |
| **机器人上门(未来)** | 老人无人在身边 | 待研发 |

**铁律**:
- **可逆操作优先**(语音提醒可放给所有家属,但不可「直接报警」未经人确认)。
- 每次执行必须带 **事件 ID**,便于 `Learn` 回溯。

**执行示例**:

```json
{
  "actions": [
    { "channel": "voice",   "target": "speaker_in_living_room", "text": "..." },
    { "channel": "wechat",  "target": "daughter",              "text": "..." },
    { "channel": "save_clip", "clip": "last_30min",            "reason": "为社区取证保留" }
  ]
}
```

---

### 3.8 Learn(学习)

**目标**:让系统越来越懂这位老人。

**反馈通道**:

1. **家属反馈**:「其实是装修,不是骗子」→ 模型应降低「陌生男性 + 长时间停留」的权重。
2. **误报修正**:同一模式 5 次都被否定 → 该模式降权。
3. **漏报学习**:未被识别的诈骗 → 该模式升权,补充进训练集。
4. **画像更新**:老人近期作息、社交圈、偏好地点持续更新。
5. **规则迭代**:风险评分公式、阈值、Plan 顺序都被纳入迭代。

**示例闭环**:

```
AI 报警:陌生人停留 40 分钟
   ↓
家属反馈:其实是装修
   ↓
Learn 层:
   1. 「装修」模式入库
   2. 「装修师傅 + 工具袋」标签 → 风险降权
   3. 下次类似场景 → 不再触发高分预警
```

```
AI 未报警
   ↓
老人被骗
   ↓
Learn 层:
   1. 「保健品会销」模式升权
   2. 「陌生电话 30min+」+ 「异地 GPS」组合 → 权重 ↑
   3. 下次类似场景 → 提前至 Evaluate 阶段触发高分
```

**设计要点**:
- 反馈必须 **轻量化** —— 家属只需「是/否」一键,否则不会填。
- 画像按 **个人粒度**,不是群体粒度 —— 系统越用越懂「**这位**老人」。

## 四、核心差异化:为什么 Evaluate + Plan 是护城河

| 维度 | 普通识别系统 | AI Risk Agent(本架构) |
| --- | --- | --- |
| 输出 | 「有风险」 | 「**风险 78 分,因为 X Y Z,建议 A→B→C 顺序响应**」 |
| 决策方式 | 固定阈值 → 固定动作 | **基于上下文动态选择资源** |
| 响应对象 | 永远通知家属 | **根据场景选最近/最可信/最匹配的资源** |
| 误报代价 | 高(打扰家属) | **分级降噪**(邻居先上、家属兜底) |
| 学习能力 | 模型级 | **画像 + 规则 + 反馈三层闭环** |
| 真实价值 | 警示 | **调度最优资源帮助老人** |

> 「**真正有价值的,不是 AI 发现风险,而是找到最优资源帮助老人**。」

## 五、典型场景全链路演示

### 场景 1:保健品会销诈骗(事前预警)

```
09:20  Perceive   摄像头:陌生人进入,无物业制服,拿宣传袋
09:35  Perceive   手机:陌生异地号码呼入
10:15  Perceive   GPS:老人离家 → 某酒店(会销高发地)

10:16  Understand 人:45 岁男性,无制服
       Understand 通信:异地号码,无历史联系
       Understand 地点:会销高发地

10:17  Predict    趋势:过去 7 天连续参加 3 次免费活动
                  偏离:从不参加讲座 → 今天去会销
                  → 风险上升

10:18  Reason     链:陌生电话(异地) → 42min → 离家 → 会销酒店 → 陌生人陪同
                  → risk_score: 78

10:19  Evaluate   level: high, type: 保健品会销
                  紧迫度:30min, 置信度:0.82
                  解释:陌生来电后,老人前往高风险地点并由陌生人陪同

10:19  Plan       primary:   邻居(3min,上门确认)
                  secondary: 家属(12min,视频通话)
                  tertiary:  物业(20min,可拦截)
                  fallback:  社区网格员(30min)
                  self:      客厅音箱语音提醒 + 保存录像

10:20  Act        播放语音「爸,有什么事等我回家再说」→ 推送女儿微信 → 保存录像

10:50  Act        老人返回,女儿已视频确认 → 邻居/物业撤出

11:00  Learn      家属反馈:已劝回,模式入库,「异地电话 + 会销酒店」权重 ↑
```

### 场景 2:老人家中疑似跌倒

```
06:30  Perceive   摄像头:客厅长时间无人活动
06:30  Perceive   门磁:大门未开(老人未外出)
06:30  Perceive   GPS:信号弱 → 推断仍在室内
06:32  Reason     偏离:老人通常 06:00 起夜,06:30 仍未见活动 → 异常

06:32  Evaluate   level: medium-high, type: 跌倒/晕厥
                  紧迫度:15min

06:32  Plan       primary:   邻居-王阿姨(3min,敲门确认)  ← 不是家属!
                  secondary:  120(若邻居 5min 无响应)
                  fallback:   家属-女儿(异地,信息同步)

06:35  Act        邻居到场 → 确认跌倒 → 已叫 120 → 通知女儿

06:55  Learn      画像:老人 06:00–07:00 卫生间使用频率高 → 下次类似偏离,降低「跌倒」权重
```

**关键差异**:
- 同样是高风险事件,**诈骗场景**的最佳资源是「家属 + 远程介入」。
- **跌倒场景**的最佳资源是「邻居 + 急救」,而不是远在外地的家属。

这就是 `Plan` 层的价值。

## 六、与传统识别系统的边界对照

| 层 | 普通系统是否具备 | 本架构 |
| --- | --- | --- |
| Perceive | ✅ | ✅ |
| Understand | 部分 | ✅ 标签化版本 |
| Predict | ❌ | ✅ |
| Reason | ❌(单点) | ✅ 跨源因果 |
| Evaluate | ✅ 但不可解释 | ✅ 可解释、有置信度 |
| **Plan** | **❌** | **✅ 资源调度核心** |
| Act | ✅ 单一通道 | ✅ 多通道编排 |
| Learn | ❌ 离线训练 | ✅ 在线反馈闭环 |

---

## 七、总结

**八层架构的本质,是把一个黑箱 LLM,拆成一条可审计、可解释、可调度的工程流水线。**

其中最关键的一步,是把传统 `Decide` 拆成:

- **Evaluate**:告诉你风险有多大、为什么。
- **Plan**:告诉你 **谁去救**、按什么顺序。

这两层的拆分,让系统从「AI 识别风险」跨越到「**AI 风险决策与资源调度**」 —— 这才是本项目真正有价值、最难被复制、最贴近「帮助老人」这件事本身的部分。

---

> **附:数据流简写**
> `Perceive → Understand → Predict → Reason → Evaluate → Plan → Act → Learn → 回到 Perceive`
> 闭环,持续迭代。
