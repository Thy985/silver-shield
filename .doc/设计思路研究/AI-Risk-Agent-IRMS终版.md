# 银龄盾 · 智能风险管理系统(IRMS)终版

> **这不再是一个反诈骗系统,而是一套完整的智能风险管理系统**
> **(Intelligent Risk Management System, IRMS)**。
>
> 它把诈骗视为 **连续演化过程**,把老人、访客、活动、机构都纳入 **统一世界模型**,
> 通过 **资源调度** 而非简单推送完成干预,通过 **主动学习** 持续自我进化。

---

## 产品哲学(贯穿全文)

**AI 不是决策者,而是「帮助老人相信正确的人」+「调度最优响应资源」。**

```
不是:  AI: "这是诈骗。"
而是:  AI: "建议联系您的儿子确认。"
       或
       AI: "社区王阿姨已经帮您核验,该活动不存在备案。"

不是:  AI: "已通知家属。"
而是:  AI: 调度算法运行 → 家属未响应 → 升级社区 → 社区未响应 → 升级物业 → 升级 110。
```

防诈骗真正的难点,从来不是「识别」,而是 **让老人愿意接受帮助 + 让合适的人在合适的时间介入**。
所以 IRMS 的核心不是「识别诈骗」,而是 **「风险管理」+「资源调度」**。

---

## 项目定位(一句话贯穿)

> **银龄盾 IRMS 是一个持续进化的智能风险管理系统,具备 10 层循环能力(Perceive→Understand→Memory→Reason→Risk Evolution→Decision→Resource Scheduling→Action→Feedback→Learn),维护一份统一的「世界模型与知识图谱」,并通过「资源调度」而非简单推送完成干预。**

## 一、系统核心竞争力(10 项 · vs 市面方案)

> **不写功能写能力。这一页是产品 vs 功能的本质差异。**

| # | 能力维度 | 市面方案 | **银龄盾 IRMS** |
| --- | --- | --- | --- |
| 1 | **连续感知** | 单点检测 | **全流程持续感知**(7×24 主动采集 + 异常触发) |
| 2 | **可解释 AI** | 黑盒预警 | **多模态证据链 + 增量式解释**(每条预警 +N 的来源) |
| 3 | **智能决策** | 固定规则 | **Rule + ML + LLM 三层决策** |
| 4 | **长期记忆** | 无 | **世界模型与知识图谱**(老人/访客/活动/机构统一画像) |
| 5 | **主动学习** | 无 | **反馈驱动的全社区级学习闭环** |
| 6 | **多方协同** | 单人提醒 | **老人-家属-社区-物业-机构-公安协同网络** |
| 7 | **信任增强** | 强制提醒 | **AI 不是决策者,是信任桥梁** |
| 8 | **服务闭环** | 通知即结束 | **处理 → 反馈 → 学习 → 规则更新 → 画像升级** |
| 9 | **风险演化建模** | 静态判断 | **过程建模**(接触→信任→操控→诱导→交易→被骗,六阶段动态曲线) |
| 10 | **资源调度** | 通知家属 | **动态资源调度算法**(可达性+距离+能力+信任+成本,自动升级) |

> **这 10 项不是 10 个功能,而是 10 种能力** —— 这就是「产品 vs 功能」的本质差异。

## 三、10 层架构总览(IRMS Agent · 显式化)

> **必须明确:这是一个 IRMS Agent,不是一个 AI 监测系统。**

```
                  ┌──────────────────────────────────────┐
                  │   Memory Agent(世界模型与知识图谱)  │
                  │   Elder / Visitor / Activity / Org   │
                  │   ↑↓ 持续读写                        │
                  └──────────────────────────────────────┘
                                ↑↓
        ┌─────────────────────────────────────────────────────┐
        │                                                     │
        │   Perceive(感知)              → 风险发现             │
        │        ↓                                            │
        │   Understand(理解)            → 风险证据             │
        │        ↓                                            │
        │   Memory(长期记忆)            → 知识查询             │
        │        ↓                                            │
        │   Reason(推理)                → 风险解释             │
        │        ↓                                            │
        │   Risk Evolution(风险演化)    → 阶段判断             │
        │        ↓                                            │
        │   Decision(智能决策)          → 干预方案             │
        │        ↓   Rule + ML + LLM                          │
        │   Resource Scheduling(资源调度) → 选谁、顺序         │
        │        ↓                                            │
        │   Action(协同干预)            → 多通道执行           │
        │        ↓   + Trust Enhancement                      │
        │   Feedback(结果反馈)          → 闭环数据             │
        │        ↓                                            │
        │   Learn(主动学习)             → 规则/画像/模型升级  │
        │                                                     │
        │        ↓ 回到 Perceive(世界模型持续更新)            │
        └─────────────────────────────────────────────────────┘
```

**关键说明**:
- 10 层循环,不是分层架构,而是 **Agent 的 10 个能力模块**。
- **Memory Agent** 维护世界模型与知识图谱,是中枢。
- **Risk Evolution Agent** 是新增,处理「连续过程」。
- **Resource Scheduling Agent** 是强化,处理「调度最优资源」。
- **Learn** 显式化为最后一步,体现「主动学习闭环」。

**协同网络的 8 个节点**:

| 节点 | 角色 | 数据贡献 | 响应能力 |
| --- | --- | --- | --- |
| **老人** | 风险主体 | 自身行为数据 | 接收提醒 |
| **家庭/家属** | 一级响应 | 误报/确认反馈 | 远程视频、决策 |
| **邻居** | 二级响应(就近) | 旁观信息 | 上门确认 |
| **物业** | 二级响应(本地) | 小区活动信息 | 上门拦截 |
| **社区** | 三级响应 | 群体活动备案 | 网格员介入 |
| **养老机构** | 服务响应 | 老人健康数据 | 健康监测联动 |
| **反诈中心** | 业务响应 | 诈骗情报库 | 案件协查 |
| **公安/110** | 应急响应 | 案件信息 | 紧急出警 |

**风险共享机制**:
- 每个节点都贡献数据,也消费数据。
- 同一诈骗团伙 / 同一可疑机构 → **所有节点同时预警**。
- 形成「**群体防护**」效应,而不是单点防御。

## 六、How(智能层)—— IRMS Agent 10 大模块

> **本人主导。这是 IRMS 的核心循环。**

### 6.1 Perceive Agent(感知 · 风险发现)

**目标**:眼睛和耳朵。
**输出**:结构化原始事件流。

**关键设计**:
- 全部输出带 `timestamp` + `source`,可追溯。
- 异常信号(掉线、采集失败)必须显式上报。

---

### 6.2 Understand Agent(理解 · 风险证据)

**目标**:把事实变成证据。
**输出**:多模态标签。

---

### 6.3 Memory Agent(长期记忆 · 世界模型)

> **这是 IRMS 的灵魂中枢。详见第八章「世界模型与知识图谱」。**

**目标**:让 IRMS 越来越懂这位老人、这个访客、这场活动、这家机构。

---

### 6.4 Reason Agent(推理 · 风险解释)

**目标**:给出可解释的因果链。

---

### 6.5 Risk Evolution Agent(风险演化 · 阶段判断)—— NEW

> **这是新增的核心模块。详见第九章「风险演化模型」。**

**目标**:把诈骗视为 **连续过程**,判断老人「走到了第几阶段」,而非「一次性事件」。

---

### 6.6 Decision Agent(智能决策)

**目标**:决定「该不该干预、谁来干预、按什么顺序」。

> **风险引擎三层:RULE + ML + LLM**

```
Layer 1 · Rule Engine(毫秒级强信号)
   验证码 + 银行卡 + 保密 → 直接高危
   陌生号码 + 通话 > 30min → 中危

Layer 2 · ML Model(概率化)
   XGBoost / 轻量神经网络
   输入:多模态标签 + 画像
   输出:风险分数(0-100)

Layer 3 · LLM Reasoning(可解释)—— 第二版
   把数字翻译成「人话」
   输出:可解释结论 + 干预建议
```

**MVP 第一版**:Rule + ML 两层,**LLM 留第二版**。

---

### 6.7 Resource Scheduling Agent(资源调度 · 强化)

> **这是核心差异化能力。详见第十章「资源调度」。**

**目标**:动态选择「谁」介入、按「什么顺序」、超时如何「升级」。

---

### 6.8 Action Agent(协同干预 · 风险响应)

**目标**:把决策真正落到现实。

```
Decision → 干预方案
   ↓
Resource Scheduling → 资源调度顺序
   ↓
Trust Enhancement → 信任策略注入
   ↓
多通道协同执行:
  - 本地语音(Home Agent)
  - 微信/App(Family Agent)
  - 短信(异地家属)
  - 社区平台(Community Agent)
  - 录像保存(Memory Agent)
   ↓
执行反馈 → Feedback Agent
```

---

### 6.9 Feedback Agent(结果反馈 · 闭环数据)

**目标**:每一次干预都收集反馈数据。

**反馈来源**:
- **家属反馈**:误报标记、模式修正、画像更新
- **社区反馈**:群体模式修正、上门结果
- **老人行为反馈**:干预后行为是否改变
- **系统执行反馈**:响应时间、是否成功触达

---

### 6.10 Learn Agent(主动学习 · 强化)

> **这是 Learn 模块的显式化升级。详见第十一章「主动学习闭环」。**

**目标**:让每一次干预都让 IRMS 更准。

**三种学习范式**:
| 类型 | 触发 | 学习动作 |
| --- | --- | --- |
| 误报降权 | 家属标记「是装修」 | 模式降权、阈值上调 |
| 漏报升权 | 老人真的被骗 | 模式升权、阈值下调 |
| 群体学习 | 同一机构连续 5 次真诈骗 | 该机构全社区风险升级、画像共享 |

## 八、世界模型与知识图谱(Memory Agent 的核心)

> **这是新增的核心章节。统一的数据模型是 IRMS 区别于普通 AI 系统的根本。**

### 8.1 为什么必须建立「世界模型」

> 多数 AI 系统每次都 **重新判断**,不利用已有知识。
> IRMS 维护一份 **世界模型**,任何事件都是「查询世界知识」,而不是「从零分析」。

### 8.2 四类画像的统一数据模型

#### ① 老人画像(Elder Profile)

```
elder_id: "elder_001"
├── 基础档案
│   ├── 年龄、性别、独居状态
│   └── 健康、性格、数字能力
├── 家庭关系
│   ├── 女儿(异地,信任度 0.92)
│   └── 邻居王阿姨(本地,信任度 0.85)
├── 行为基线
│   ├── 作息、外出、社交、偏好
├── 风险偏好
│   ├── 易受骗程度(vulnerability)
│   ├── 风险敏感度
│   └── 历史被骗记录
└── 数字能力
    ├── 是否会用智能手机
    └── 是否经常扫码
```

#### ② 访客画像(Visitor Profile)

```
visitor_id: "visitor_unknown_001"
├── 首次出现时间
├── 出现频率(连续 3 天)
├── 出现时间(下午 3 点,符合会销节奏)
├── 停留时长(平均 42 分钟)
├── 同行人数(1-2 人,频繁更换)
├── 是否多次更换身份(是的,不同服装)
├── 携带物品(宣传袋、礼品)
└── 历史事件(无登记,3 次到访)
```

```
├── 举办地点:某酒店(会销高发地)
├── 举报次数:历史 12 次举报

```

## 九、风险演化模型(Risk Evolution Agent · 阶段判断)

> **诈骗不是事件,是过程。**

### 9.1 诈骗六阶段模型

```
接触 → 建立信任 → 长期情感操控 → 诱导 → 交易 → 被骗
 20      35         50            65      82      97
```

| 阶段 | 名称 | 典型信号 | 风险分 | 干预策略 |
| --- | --- | --- | --- | --- |
| 1 | **接触** | 第一次陌生号码、第一次陌生人上门 | 20 | 记录画像 |
| 2 | **建立信任** | 第二次上门、关心话术、赠送小礼品 | 35 | 提醒家属注意 |
| 3 | **长期情感操控** | 连续 3+ 天到访、强调「不要告诉孩子」 | 50 | 推送家属视频 |
| 4 | **诱导** | 提出「稳赚」「内部消息」、要求保密 | 65 | 启动资源调度 |
| 5 | **交易** | 让带银行卡、扫码付款 | 82 | 紧急干预,联系家属/社区 |
| 6 | **被骗** | 老人已付款、事后回忆 | 97 | 应急响应 + 复盘 + 学习 |

### 9.2 风险动态增长曲线

```
风险
100 ┤                                      ●←被骗
    │                                  ●
 80 ┤                              ●       ←交易
    │                          ●
 60 ┤                      ●               ←诱导
    │                  ●
 40 ┤              ●                       ←操控
    │          ●
 20 ┤      ●                               ←建立信任
    │  ●                                   ←接触
  0 ┼────────────────────────────────────
    第1次 第2次 第3次 第4次 第5次 第6次
```

### 9.3 阶段识别算法

```
输入:多模态标签 + 历史画像 + 世界模型
输出:当前阶段 + 风险分 + 推荐干预

伪代码:
def identify_stage(event, elder_profile, world):
    contact_count = elder_profile.recent_visitor_count
    has_gift = event.tags.get('gift', False)
    has_secret = event.speech.keywords.has('保密')
    has_card = event.tags.get('elder_card', False)
    has_payment = event.tags.get('qr_scan', False)

    if contact_count == 0:
        return Stage.CONTACT, 20, '记录画像'
    if contact_count == 1 and has_gift:
        return Stage.TRUST_BUILDING, 35, '提醒家属'
    if contact_count >= 3 and has_secret:
        return Stage.MANIPULATION, 50, '推送家属视频'
    if has_secret and ('稳赚' in event.speech or '内部' in event.speech):
        return Stage.INDUCTION, 65, '启动资源调度'
    if has_card or has_payment:
        return Stage.TRANSACTION, 82, '紧急干预'
    if has_payment and elder_profile.suspicious_outcome:
        return Stage.SCAMMED, 97, '应急+复盘'
```

### 9.4 阶段识别对干预的指导意义

| 当前阶段 | 不应做的事 | 应该做的事 |
| --- | --- | --- |
| **接触(20)** | 升级报警 | 记录、观察 |
| **建立信任(35)** | 强制干预 | 提醒家属注意 |
| **操控(50)** | 等待 | 推送家属视频介入 |
| **诱导(65)** | 仅推送 | **启动资源调度**(家属+社区+物业) |
| **交易(82)** | 等反馈 | **紧急多通道干预** |
| **被骗(97)** | 通知 | **应急响应+复盘+学习** |

## 十、资源调度(Resource Scheduling Agent · 强化)

> **这是最早提出来的核心差异化能力,这一版必须讲透。**

### 10.1 为什么必须做资源调度

> **多数 AI 系统止步于「通知家属」,银龄盾要做的是「调度最优响应」**。
> 晚上十点、儿子国外、社区未响应、物业未响应、110 —— 这才是真实场景。

### 10.2 资源池(8 节点)

```
┌──────────────────────────────────────┐
│         IRMS 资源池(8 节点)         │
├──────────────────────────────────────┤
│ 一级(快速):家属(本地)、邻居、物业    │
│ 二级(中速):家属(异地)、社区、机构    │
│ 三级(应急):反诈中心、公安/110、保险  │
└──────────────────────────────────────┘
```

### 10.3 调度维度(5 维)

| 维度 | 含义 | 示例 |
| --- | --- | --- |
| **可达性** | 资源当前是否可用? | 家属是否在上班、邻居是否在家 |
| **距离/响应时间** | 多久能到场? | 邻居 3min vs 异地家属 2h |
| **能力匹配** | 资源的能力是否匹配场景? | 跌倒→急救;诈骗→家属;暴力→警方 |
| **信任度** | 老人对资源的信任关系? | 老人更信任女儿而非儿子 |
| **成本** | 误报社会成本? | 打扰家属次数、社区资源占用 |

### 10.4 调度算法(伪代码)

```python
def schedule_resources(risk_event, elder, world):
    candidates = []
    for resource in RESOURCE_POOL:
        score = (
            reachability(resource) * 0.30 +
            (1 / response_time(resource)) * 0.25 +
            capability_match(resource, risk_event.type) * 0.20 +
            trust_score(resource, elder) * 0.20 +
            (1 - cost_score(resource)) * 0.05
        )
        candidates.append((resource, score))

    candidates.sort(key=lambda x: -x[1])

    # 三级响应链
    schedule = {
        'primary':   candidates[0],
        'secondary': candidates[1],
        'tertiary':  candidates[2],
        'fallback':  candidates[3],
    }

    # 设置升级超时
    schedule['primary'].timeout = 5*60      # 5 分钟
    schedule['secondary'].timeout = 15*60   # 15 分钟
    schedule['tertiary'].timeout = 30*60    # 30 分钟
    schedule['fallback'].timeout = 60*60    # 60 分钟

    return schedule
```

### 10.5 升级路径与超时机制

```
场景:晚上 22:00,老人接 40min 诈骗电话,准备转账
时间轴:
22:00  一级响应 → 邻居王阿姨(3min 内上门)
       超时 5min,未响应
22:05  二级响应 → 家属-女儿(女儿视频通话接入)
       女儿确认后请求社区协助
22:20  三级响应 → 社区网格员(本社区已值班)
       网格员上门
22:50  应急响应 → 反诈中心(若已转账,联动止付)
```

### 10.6 场景对比

| 场景 | 风险 | 调度路径 |
| --- | --- | --- |
| **老人家中疑似跌倒** | 中高 | **邻居(3min)→ 120 → 家属通知** |
| **接到疑似诈骗电话** | 高 | **本地语音提醒 → 家属视频 → 社区** |
| **疑似会销被困** | 高 | **家属视频 + 物业拦截 双线** |
| **独居老人失联** | 高 | **物业敲门 + 网格员 + 公安** |
| **老人准备转账** | 极高 | **家属 + 反诈中心同步,紧急止付** |

> 第二版加入智能调度算法。

## 十一、证据链与可解释 AI(Reason Agent 强化)

> **评委最怕「为什么 80 分不知道」。这一章讲透解释型 AI。**

### 11.1 增量式证据链(不是总分,而是「+N」的累加)

```
风险等级:高

原因一:陌生访客连续三天来访 ........... +15
原因二:老人今天第一次拿出银行卡 ....... +25
原因三:检测到「不要告诉孩子」关键词 .... +30
原因四:历史已有三位老人举报该机构 ...... +20
                                       ─────
综合评分:                                90

解释置信度: 0.92
```

### 11.2 三层证据结构

| 层级 | 来源 | 示例 |
| --- | --- | --- |
| **信号层** | 实时感知事件 | 「陌生访客」「银行卡」「关键词」 |
| **画像层** | 老人/访客/活动画像 | 「老人易受骗程度 0.78」「该访客已出现 3 次」 |
| **知识层** | 世界模型与知识图谱 | 「该机构历史投诉 8 次」「同社区 3 位老人被骗过」 |

### 11.3 可视化证据链(给家属/社区看)

```
风险来源占比:
┌─────────────────────────────────┐
│ 陌生访客连续到访   ████░░░░░░ 15%  │
│ 老人首次拿银行卡   ██████░░░░ 25%  │
│ 关键词「不要告诉」████████░░ 30%  │
│ 机构历史投诉       █████░░░░░ 20%  │
│ 画像易受骗度       ██░░░░░░░░ 10%  │
└─────────────────────────────────┘
综合:90 高风险
```

> **这就是「Explainable AI」** —— 不只是数字,而是「+N」的可读证据。

## 十二、主动学习闭环(Learn Agent · 显式化)

> **每一次干预都让 IRMS 更准。**

### 12.1 三种学习范式

#### ① 单点学习(每位老人)

```
AI 判断「陌生人是骗子」(风险 85)
   ↓
家属反馈「其实是装修」(误报)
   ↓
Learn:
   - 「装修师傅 + 工具袋」模式入库
   - 该老人画像:陌生人停留时间阈值上调
   - 下次类似场景 → 不再触发高分预警
```

#### ② 群体学习(社区级)

```
AI 判断「某机构活动」(风险 70)
   ↓
社区反馈「该机构已被举报 5 次,确认诈骗」
   ↓
Learn:
   - 该机构画像风险等级升级为「高」
   - 该社区所有老人收到群体预警
   - 该机构关联访客进入黑名单
```

#### ③ 跨社区学习(平台级)

```
A 社区出现新型诈骗手法
   ↓
IRMS 检测到该模式首次出现
   ↓
Learn:
   - 新模式入库为「待观察」
   - 同步到 B、C 社区的 IRMS 节点
   - 跨社区群体防护
```

### 12.2 反馈驱动机制

| 反馈类型 | 触发 | 学习动作 |
| --- | --- | --- |
| 误报降权 | 家属标记「是装修」 | 模式降权、阈值上调 |
| 漏报升权 | 老人真的被骗 | 模式升权、阈值下调 |
| 成功入库 | 家属确认「已劝回」 | Trust 策略权重 ↑ |
| 群体升级 | 同机构 5 次真诈骗 | 全社区风险升级、画像共享 |
| 跨域迁移 | 新社区出现新模式 | 全平台同步 |

## 十六、答辩统一表述(完整版 · 可直接复用)

> 我们构建的不是一个反诈 AI 功能,而是一个 **智能风险管理系统(IRMS, Intelligent Risk Management System)** —— 银龄盾。
>
> 它把诈骗视为 **连续演化过程**,而不是一次性事件。它维护一份统一的 **世界模型与知识图谱**(老人、访客、活动、机构),让所有判断都基于已有知识,而非从零分析。它通过 **资源调度** 而非简单推送完成干预,动态选择「谁」介入、按「什么顺序」、超时如何「升级」。它通过 **主动学习** 持续自我进化,每一次干预都让系统更准。
>
> IRMS 拥有 **10 层循环能力**:Perceive → Understand → Memory → Reason → Risk Evolution → Decision → Resource Scheduling → Action → Feedback → Learn。
>
> 系统部署在 **Home + Mobile + Family + Community** 四端,通过 **8 节点协同网络**(老人/家属/邻居/物业/社区/养老机构/反诈中心/公安)共享风险。
>
> 我们的产品哲学是:**AI 不是决策者,而是「帮助老人相信正确的人 + 调度最优响应资源」**。
>
> 核心壁垒不是某个模型,而是 **三种长期资产**:统一的 **世界模型与知识图谱**、反馈驱动的 **主动学习闭环**、8 节点共享的 **协同防护网络**。这三件事,竞品难以复制。
>
> 第一版我们没有做 AI 换脸、AI 拟声、LLM Reasoning,因为两个月做不完。**我们只做一件事:让一个独居老人,在被骗之前 30 分钟,被合适的人在合适的时间拦下来**。资源调度、知识图谱、风险演化都是这一件事的支撑能力。
>
> 这不是一个比赛作品,而是一个 **数字守护平台** —— 用一个持续进化的 IRMS,守护每一位独居老人。
