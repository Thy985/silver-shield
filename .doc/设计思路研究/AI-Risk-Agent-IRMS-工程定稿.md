# 银龄盾 IRMS · 工程定稿版

> **这不再是一个反诈骗系统,而是一套完整的智能风险管理系统**
> **(Intelligent Risk Management System, IRMS)**。
>
> 它把诈骗视为 **连续演化过程**,把老人、访客、活动、机构都纳入 **统一世界模型**,
> 通过 **资源调度** 而非简单推送完成干预,通过 **主动学习** 持续自我进化。
>
> —— 本文是面向答辩的工程定稿版,聚焦 **数据来源可信度、Learn 可信度、实验可信度、商业可信度**。

---

## 产品哲学

**AI 不是决策者,而是「帮助老人相信正确的人」+「调度最优响应资源」。**

---

## 项目定位(一句话贯穿)

> **银龄盾 IRMS 是一个持续进化的智能风险管理系统,具备 10 个能力模块的循环感知与决策能力,维护一份统一的「世界模型与知识图谱」,通过「资源调度」而非简单推送完成干预。**

### 7.6 风险引擎:Rule + ML 两层(LLM 不在 MVP)

> **重要调整**:第一版只实现 Rule + ML 两层,**LLM Reasoning 暂不引入**。
> 原因:Rule + ML + 知识图谱已能覆盖 MVP 场景;LLM 在数据稀疏时容易产生幻觉,工程可信度不足。

```
Layer 1 · Rule Engine(毫秒级强信号)
   验证码 + 银行卡 + 保密 → 直接高危
   陌生号码 + 通话 > 30min → 中危
   独居老人 + 夜间外出 → 中危

Layer 2 · ML Model(概率化)
   XGBoost
   输入:多模态标签 + 画像
   输出:风险分数(0-100) + 异常程度

(Layer 3 · LLM Reasoning · 第二版)
   输入:ML 分数 + 证据链 + 画像
   输出:可读解释 + 干预建议
```

**为什么 Rule + ML 已足够**:
- 规则层捕获「绝对强信号」(毫秒级、可解释、零误报容忍)
- ML 层处理「弱信号组合」(概率化、可学习)
- 知识图谱提供「外部知识」(机构历史投诉、关联访客)
- LLM 的可解释性优势,可以通过 **增量式证据链 + 可视化** 部分替代

## 九、世界模型与知识图谱(Memory 模块)

### 9.1 为什么需要世界模型

多数 AI 系统每次都 **重新判断**,不利用已有知识。
IRMS 维护一份 **世界模型**,任何事件都是「查询世界知识」,而不是「从零分析」。

### 9.2 四类画像

| 画像 | 关键字段 | 价值 |
| --- | --- | --- |
| 老人画像 | 行为基线、家庭关系、易受骗程度、被骗史、健康、性格、数字能力 | 偏离检测、个性化阈值 |
| 访客画像 | 出现频率、停留时长、是否换装、是否同行 | 陌生关系识别 |
| 活动画像 | 地点、举报次数、是否备案、收费、历史参与人数 | 群体风险识别 |
| 机构画像 | 名字、联系电话、关联二维码、投诉次数、关联活动/访客 | 团伙识别 |

> 详细字段定义与 JSON Schema 见附录 A。

### 9.3 知识图谱数据来源 ★ —— 关键可信度

> **评委一定问:「这些知识图谱从哪里来?」**
> **这一节就是答案。**

| 数据来源 | 维护方式 | MVP 第一版 |

| **人工录入** | 项目运营人员统一录入 | ✅ |
| **社区网格员上报** | 社区端工单系统,网格员上传活动/机构信息 | ✅ |

### 9.4 MVP 知识图谱维护流程

```
新事件发生
   ↓
自动提取实体(访客/活动/机构名)
   ↓
匹配已有画像
   ├─ 命中 → 更新属性
   └─ 未命中 → 推入「待审核」队列
                  ↓

                  └─ 拒绝 → 标注噪声,丢弃
```

## 十、风险演化模型(Risk Evolution 模块)

### 10.1 诈骗六阶段

| 阶段 | 典型信号 | 风险分 | 干预策略 |
| --- | --- | --- | --- |
| 1 接触 | 第一次陌生号码、上门 | 20 | 记录画像 |
| 2 建立信任 | 第二次上门、关心话术、赠送小礼品 | 35 | 提醒家属 |
| 3 长期情感操控 | 连续 3+ 天到访、「不要告诉孩子」 | 50 | 推送家属视频 |
| 4 诱导 | 提出「稳赚」「内部」、要求保密 | 65 | 启动资源调度 |
| 5 交易 | 让带银行卡、扫码付款 | 82 | 紧急多通道干预 |
| 6 被骗 | 老人已付款 | 97 | 应急 + 复盘 + 学习 |

### 10.2 阶段识别对干预的指导意义

- **阶段 1-2**:记录为主,不升级干预(避免噪声)。
- **阶段 3-4**:资源调度启动,选最优响应资源。
- **阶段 5-6**:紧急多通道协同,所有节点联动。

> 阶段识别算法伪代码见附录 B.1。

### 10.3 MVP 第一版实现

> 第一版 **不训练 ML 阶段识别模型**,而是用 **规则 + 阈值匹配**:
> - 阶段 1:陌生号码次数 = 1
> - 阶段 2:陌生号码次数 ≥ 2 OR 出现「礼品」「免费」关键词
> - 阶段 3:陌生到访 ≥ 3 天 OR 出现「不要告诉孩子」

## 十一、资源调度(Resource Scheduling · ✅ Agent)

### 11.1 为什么必须做资源调度

> **多数 AI 系统止步于「通知家属」,银龄盾要做的是「调度最优响应」**。
> 晚上十点、儿子国外、社区未响应、物业未响应、110 —— 这才是真实场景。

### 11.2 资源池(8 节点)与 MVP 三级

| 响应级 | 资源 | MVP 第一版 | 适用 |
| --- | --- | --- | --- |
| 一级(快速) | 家属(本地)、邻居、物业 | ✅ | 5min 内到场 |
| 二级(中速) | 家属(异地)、社区、机构 | ✅ | 30min 内响应 |
| 三级(应急) | 反诈中心、公安/110、保险 | ✅ | 立即(尤其涉及转账) |

### 11.3 5 维调度维度

| 维度 | 含义 |
| --- | --- |
| 可达性 | 资源当前是否可用 |
| 距离/响应时间 | 多久能到场 |
| 能力匹配 | 资源能力是否匹配场景 |
| 信任度 | 老人对资源的信任关系 |
| 成本 | 误报社会成本 |

### 11.4 升级超时机制

```
22:00  一级响应 → 邻居王阿姨(3min 内上门)
       超时 5min,未响应
22:05  二级响应 → 家属-女儿(女儿视频通话接入)
22:20  三级响应 → 社区网格员
22:50  应急响应 → 反诈中心(若已转账,联动止付)
```

### 11.5 MVP 第一版 · 简化

> 第一版只做 **三级调度**,不做动态升级算法。

| 响应级 | 资源 | 超时 |
| --- | --- | --- |
| 一级 | 家属 | 5min |
| 二级 | 社区 | 15min |

## 十三、主动学习闭环(Learn · ✅ Agent · 人工化调整)

> **关键调整:Learn 模块第一版采用「人工审核 + 离线重训」,而非在线自动学习。**

### 13.1 为什么第一版不引入在线学习

- 数据稀疏,在线学习容易「学坏」(被噪声带偏)
- 模型行为难以审计,出问题时难以追溯
- 比赛现场评委质疑概率高

### 13.2 第一版 Learn 工作流(稳健)

```
Feedback Agent 采集反馈
   ↓
每周汇总到「待审核」队列
   ├─ 误报反馈 N 条
   ├─ 漏报反馈 M 条
   └─ 成功反馈 K 条
   ↓
人工审核(项目运营 + 社区网格员)
   ├─ 确认有效 → 推入训练集
   └─ 确认无效 → 归档,不入训练
   ↓
满足条件(累积 ≥ 50 条 OR 误报率突增)
   ├─ 是 → 触发离线重训(XGBoost 增量训练)
   └─ 否 → 继续累积
   ↓
离线重训 + A/B 测试(新旧模型对比)
   ├─ 新模型更优 → 部署上线
   └─ 新模型更差 → 保留旧模型
```

### 13.3 第二版升级(在线增量)

> 第二版在数据量充足、模型行为可审计后,引入 **在线增量学习**:
> - 增量训练频率:每周一次,人工触发
> - 自动监控:误报率突增 → 自动回滚
> - 行为审计:每次模型变更记录训练数据 + 评估指标

### 13.4 三种学习范式

| 范式 | 范围 | 触发 |
| --- | --- | --- |
| 单点学习 | 单个老人 | 家属反馈误报/漏报 |
| 群体学习 | 整个社区 | 同一机构连续 5 次真诈骗 |
| 跨域迁移 | 跨社区 | 新社区出现新模式(全平台同步) |

> Learn Agent 状态机见附录 B.4。

## 十七、未来演进:Risk OS(家庭智能风险操作系统)★

```
现在:  IRMS = 反诈系统
未来:  Risk OS = 家庭智能风险操作系统

Risk OS Core(核心不变)
   ├── Perceive → Understand → Memory → Reason
   ├── Risk Evolution → Decision
   ├── Resource Scheduling → Action

Risk Plugin(插件可替换)
```

### 17.2 为什么这是合理的演进

- **核心能力不变**:感知、推理、记忆、决策、调度、执行、反馈、学习 —— 这些是 **任何风险场景的通用能力**。
- **插件可替换**:换不同的感知模型 + 不同的标签体系 + 不同的干预策略,就能服务新场景。
- **数据资产复用**:世界模型、知识图谱、协同网络,在新场景中 **直接复用**,无需重建。

## 十八、答辩统一表述

> 我们构建的不是一个反诈 AI 功能,而是一个 **智能风险管理系统(IRMS)** —— 银龄盾。
>
> 它把诈骗视为 **连续演化过程**,而不是一次性事件。它维护一份统一的 **世界模型与知识图谱**,让所有判断都基于已有知识,而非从零分析。它通过 **资源调度** 而非简单推送完成干预,动态选择「谁」介入、按「什么顺序」、超时如何「升级」。它通过 **稳健的 Learn 闭环**(人工审核 + 离线重训)持续自我进化。
>
> IRMS 拥有 **10 个能力模块**(Perceive / Understand / Memory / Reason / Risk Evolution / Decision / Resource Scheduling / Action / Feedback / Learn),其中 Resource Scheduling 与 Learn 两个模块具备完整 Agent 特征。
>
> 系统部署在 **Home + Mobile + Family + Community** 四端,通过 **8 节点协同网络** 共享风险。
>
> 数据来源完全透明:每一种感知信号都对应具体的数据源、模型选型、算力部署位置(详见 Observable Signals 表)。知识图谱第一版由人工维护 + 社区录入 + 家属反馈 + 公安公开案例构成,**我们不假装全自动,而是稳健推进**。
>
> 商业模式覆盖 **7 方生态**:政府/民政/物业/运营商/萤石/反诈中心/保险,通过 SaaS 订阅 + 政府购买 + 渠道分成多元变现。
>
> 第一版我们没有做 LLM、AI 换脸、在线自动学习,因为两个月做不完,且工程可信度不够。**我们只做一件事:让一个独居老人,在被骗之前 30 分钟,被合适的人在合适的时间拦下来**。在我们的实验中,这一时间差是普通方案的近 10 倍。
>
> 我们的真正终局不是反诈平台,而是 **Risk OS(家庭智能风险操作系统)** —— 同一套核心架构,通过插件化扩展,服务诈骗、跌倒、走失、火灾、健康等全场景风险。
>
> 这不是一个比赛作品,而是一个 **Risk OS 平台** —— 用一个持续进化的 IRMS 核心,守护每一位独居老人,守护每一个家庭。

### B.1 风险演化阶段识别(MVP 规则版)

```python
def identify_stage_rule_based(event, elder):
    count = elder.recent_visitor_count
    keywords = event.speech.keywords
    tags = event.tags

    if count == 0:
        return 'CONTACT', 20
    if count == 1 or '礼品' in keywords or '免费' in keywords:
        return 'TRUST_BUILDING', 35
    if count >= 3 or '不要告诉孩子' in keywords:
        return 'MANIPULATION', 50
    if ('稳赚' in keywords or '内部' in keywords) and '保密' in keywords:
        return 'INDUCTION', 65
    if tags.get('elder_card') or tags.get('qr_scan'):
        return 'TRANSACTION', 82
    if tags.get('transferred'):
        return 'SCAMMED', 97
    return 'UNKNOWN', 30
```

### B.2 资源调度 MVP 三级版本

```python
def schedule_resources_mvp(risk_event):
    schedule = []

    # 一级:家属
    schedule.append(('family', 5*60))

    # 二级:社区
    if risk_event.score > 70:
        schedule.append(('community', 15*60))

    # 三级:110(若涉及转账)
    if risk_event.stage == 'TRANSACTION' or risk_event.stage == 'SCAMMED':
        schedule.append(('police', 0))  # 立即

    return schedule
```

### B.3 增量式证据链构建

```python
def build_evidence_chain(event, elder, world):
    chain = []
    score = 0

    # 信号层
    if event.tags.get('stranger_streak', 0) >= 3:
        chain.append(('陌生访客连续三天来访', 15, 'signal'))
        score += 15
    if event.tags.get('elder_card'):
        chain.append(('老人今天第一次拿出银行卡', 25, 'signal'))
        score += 25
    if '不要告诉孩子' in event.speech.keywords:
        chain.append(('检测到「不要告诉孩子」关键词', 30, 'signal'))
        score += 30

    # 画像层
    if elder.vulnerability_score > 0.6:
        chain.append(('画像:老人易受骗程度偏高', 10, 'profile'))
        score += 10

    # 知识层
    org = world.visitor_to_org.get(event.tags.get('visitor_id'))
    if org and org.complaint_count >= 5:
        chain.append((f'知识图谱:{org.name} 历史投诉 {org.complaint_count} 次', 20, 'knowledge'))
        score += 20

    return chain, score
```
