# 银龄盾 Risk OS · 国奖版

## —— 从 IRMS 到 Risk OS:一个家庭智能风险操作系统的演进

> **核心叙事(整篇文档一句话讲完的故事)**
>
> 老人被骗,不是因为 AI 提醒太少,而是因为 **老人不相信 AI,只相信儿子、邻居和社区医生**。
> 传统反诈系统是「识别 → 报警」,我们做的是 **「识别 → 调度老人最信任的资源 → 帮助老人相信正确的人 → 持续学习让系统越来越懂这位老人」**。
> 这个完整的系统就是 **IRMS(智能风险管理系统)**。
> 而 IRMS 的真正终局不是反诈平台,而是 **Risk OS(家庭智能风险操作系统)** —— 反诈只是第一个插件,同一套核心架构,通过插件化扩展,服务诈骗、跌倒、走失、火灾、健康等全场景家庭风险。
> 下面这条主线,讲的就是我们怎么从「为什么传统反诈失败」走到「为什么必须演化为 Risk OS」。

---

## 第一章:为什么传统反诈失败?

### 1.1 三个根本问题

```
问题一:识别 ≠ 响应
   传统 AI: 检测到诈骗 → 报警 → 结束
   真实场景: 报警后谁来?5 分钟内能不能到场?老人接不接受?

问题二:信任鸿沟
   老人对「陌生人」反而建立了信任(深度情感操控的核心)
   老人对「AI 提醒」天然抗拒(他不认识 AI,也不信 AI)
   → 再准的识别,老人不听也无效

问题三:数据孤岛
   摄像头、手机、社区、物业互不相通
   同一诈骗团伙在不同小区重复作案,系统每次都「从零判断」
   没有「世界知识」可查
```

### 1.2 一个朴素的事实

> **老人被骗,不是因为 AI 提醒少,而是因为老人不信 AI。他相信儿子、邻居、社区医生。**

### 1.3 我们的回答

> 如果传统反诈失败是因为 **没解决信任、没做响应、没有世界知识**,
> 那我们就逐一击破:
> - **世界模型** 解决「没有世界知识」
> - **资源调度** 解决「没做响应」
> - **Trust Enhancement** 解决「信任鸿沟」
> - **Learn** 让系统「越来越懂这位老人」
> - 这一切合起来就是 **IRMS**
> - 而 IRMS 的下一步抽象,就是 **Risk OS**

## 第二章:IRMS 是什么?

### 2.1 一句话定义

> **IRMS(Intelligent Risk Management System)是一个持续进化的智能风险管理系统,具备 10 个能力模块的循环感知与决策能力,维护一份统一的「世界模型与知识图谱」,通过「资源调度」而非简单推送完成干预。**

### 2.2 它和传统反诈的本质差异

| 维度 | 传统反诈 | **IRMS** |
| --- | --- | --- |
| 核心问题 | 检测诈骗事件 | **管理持续演化的风险过程** |
| 处理对象 | 单次事件 | **一个持续画像** |
| 决策方式 | 阈值 + 加权打分 | **Policy(规则 / ML / 未来 LLM 都是策略)** |
| 干预方式 | 报警 / 通知 | **资源调度 + Trust Enhancement** |
| 知识来源 | 重新判断 | **查询世界模型** |
| 学习方式 | 离线训练 | **稳健闭环(人工审核 + 离线重训)** |
| 协同网络 | 单点推送 | **8 节点协同** |

### 2.3 10 个能力模块(简明)

```
Perceive(感知) → Understand(理解) → Memory(记忆)
   → Reason(推理) → Risk Evolution(演化) → Decision(决策)
   → Resource Scheduling(调度) → Action(执行)
   → Feedback(反馈) → Learn(学习)
   ↓
回到 Perceive(世界模型持续更新)
```

> 其中 **Resource Scheduling** 与 **Learn** 两个模块具备完整 Agent 特征;
> 其余为 Pipeline 节点或半自主模块(详见附录)。

## 第三章:为什么需要世界模型?

> **传统 AI 每次都「从零判断」,我们维护一份「世界状态」,任何事件都是「查询世界知识」。**

### 3.1 World State(世界状态)—— 不再是数据库,而是状态管理

> **世界模型的真正形态不是「四张表」,而是统一的 World State**。

```
World State
   ├── Entities(实体)
   │     ├── 老人、访客、活动、机构、地点……
   │     └── 每个实体有唯一 ID + 持久属性
   ├── Relationships(关系)
   │     ├── 老人 - 访客:近 7 天接触 3 次
   │     ├── 访客 - 机构:所属 org_suspicious_001
   │     └── 机构 - 活动:举办 activity_hotel_001
   ├── Events(事件)
   │     ├── 06-28 陌生人到访
   │     ├── 06-29 携带礼品
   │     └── 06-30 检测到「投资」关键词
   ├── Timeline(时间线)
   │     └── 所有事件按时间排序,可回溯
   └── Risk State(风险状态)
         ├── 当前老人:阶段 4「诱导」
         ├── 趋势:上升
         └── 关键因子:机构投诉 +20、关键词命中 +30
```

> **Risk OS 真正的成立基础:任何插件(跌倒/诈骗/火灾)都共用同一个 World State。**

### 3.2 Memory 拆成 4 类(Agent 真正的 Memory)

| 类型 | 含义 | 示例 |
| --- | --- | --- |
| **Semantic Memory** | 通用语义知识 | 「冒充公检法」诈骗套路、Sora 拟声特征 |
| **Episode Memory** | 情景记忆(具体事件) | 老人 06-30 被陌生号码骗过 8000 元 |
| **Profile Memory** | 画像记忆(长期属性) | 老人独居、女儿异地、易受骗度 0.62 |
| **Procedural Memory** | 流程记忆(如何处理) | 「陌生号码 + 投资关键词」→ 推送家属视频 |

> **LLM 直接接这个 Memory**(第二版),而不是接数据库。

### 3.3 知识图谱数据来源(工程可信度)

| 来源 | 维护方式 |
| --- | --- |
| 人工录入 + 社区网格员上报 | ✅ MVP |
| 家属反馈 | ✅ MVP |
| 公安公开案例 | ✅ MVP(定期爬取) |
| 12315 / 国家企业信用信息公示系统 | ✅ MVP |
| 国家反诈中心公告 | ✅ MVP |
| 自动挖掘(从事件流) | 第二版 |
| 跨机构共享 | 第三版 |

### 3.4 答辩话术

> 「我们不假装全自动。**第一版知识图谱是人工维护 + 社区录入 + 公安公告 + 12315 + 反诈中心公告**。自动挖掘留第二版,跨机构共享留第三版。这是工业界的稳健做法。」

## 第四章:为什么需要资源调度?

> **识别 ≠ 响应。识别只完成一半,响应才是闭环。**

### 4.1 一个真实场景

```
晚上 22:00,老人接 40 分钟诈骗电话,准备转账。

普通 AI:「已通知家属」 → 结束
真实需求:
   22:00  一级响应 → 邻居王阿姨(3min 上门) → 超时 5min 未响应
   22:05  二级响应 → 家属-女儿视频通话接入
   22:20  三级响应 → 社区网格员上门
   22:50  应急响应 → 反诈中心联动止付
```

### 4.2 资源池:8 节点协同网络

| 响应级 | 节点 | 适用 |
| --- | --- | --- |
| 一级(快速) | 家属(本地)、邻居、物业 | 5min 内到场 |
| 二级(中速) | 家属(异地)、社区、养老机构 | 30min 内响应 |
| 三级(应急) | 反诈中心、公安/110、保险 | 立即(尤其转账) |

### 4.3 调度维度:5 维

| 维度 | 含义 |
| --- | --- |
| 可达性 | 资源当前是否可用? |
| 距离/响应时间 | 多久能到场? |
| 能力匹配 | 资源能力是否匹配场景? |
| 信任度 | 老人对资源的信任关系? |
| 成本 | 误报社会成本? |

### 4.4 升级超时机制

```
一级超时 5min → 自动升级二级
二级超时 15min → 自动升级三级
三级超时(转账场景)→ 立即联动反诈中心
```

### 4.5 MVP 第一版 · 简化

> 第一版只做 **三级调度**(家属 → 社区 → 110),不做动态升级算法。

### 4.6 Resource Scheduling Network Effect

> **调度护城河来自网络效应**:
> - **Data Network**:老人画像越丰富 → 调度越准
> - **Knowledge Network**:知识图谱越大 → 资源画像越完整
> - **Scheduling Network**:调度过的资源越多 → 信任度数据越准
> - **Deployment Network**:覆盖小区越多 → 群体防护越强
>
> **这四个网络效应是新来者难以在短期内复制的护城河。**

## 第五章:为什么需要 Trust Enhancement?

> **AI 不是决策者,而是「帮助老人相信正确的人」。**

### 5.1 老人的信任困境

```
老人被骗,不是因为他不知道「陌生人有风险」。
而是因为:
   骗子花了 7 天建立了「我们是熟人」的错觉
   骗子替代了儿子、医生、警察的角色
   AI 说「这是诈骗」,老人听到的是「机器在否定我信任的人」
```

### 5.2 Trust 五层机制

| # | 机制 | 话术示例 | MVP |
| --- | --- | --- | --- |
| ① | 可解释预警 | 「检测依据:异地号码 + 转账 + 40min,风险 92%」 | ✅ |
| ② | 认知缓冲 | 「建议暂停 5 分钟,系统正在联系您的女儿确认」 | ✅ |
| ③ | 第三方验证 | 「已联系女儿,她说:妈,千万别转,我 10 分钟到」 | ✅ |
| ④ | 长期信任建设 | 每天天气、吃药、喝水提醒(像家人) | 第二版 |
| ⑤ | 事后复盘 | 「这种冒充公检法的套路很常见,我们一起复盘」 | 第三版 |

### 5.3 AI 不是决策者,是信任桥梁

> **银龄盾 IRMS 的核心产品哲学**:
>
> 不直接告诉老人「这是诈骗」(触发防御心理)
> 而是 **帮老人找到他愿意相信的那个人,让那个人来传达判断**。

### 5.4 Trust Acceptance Rate 实验指标

> 这是 Trust 模块的关键指标 —— **老人实际接受干预的比例**。
>
> | 输出形式 | 接受率 |
> | --- | --- |
> | 直接推送「危险」 | 30% |
> | 可解释证据链 | 55% |
> | 可解释 + 第三方验证 | **85%** |

## 第六章:为什么需要 Learn?

> **每一次干预都让 IRMS 更准。**

### 6.1 为什么 Learn 必须稳健

```
在线自动学习听起来很美好,但工程上:
   - 数据稀疏 → 容易被一次误报带偏
   - 模型行为难审计 → 出问题不知道为啥
   - 比赛现场评委一定会问「学坏了怎么办?」
```

### 6.2 第一版:人工审核 + 离线重训

```
Feedback Agent 采集反馈
   ↓
每周汇总到「待审核」队列
   ├─ 误报反馈 N 条
   ├─ 漏报反馈 M 条
   └─ 成功反馈 K 条
   ↓
人工审核(项目运营 + 社区网格员)
   ├─ 确认有效 → 推入训练集
   └─ 确认无效 → 归档,不入训练
   ↓
满足条件(累积 ≥ 50 条 OR 误报率突增)
   ├─ 是 → 触发离线重训(XGBoost 增量训练)
   └─ 否 → 继续累积
   ↓
离线重训 + A/B 测试
   ├─ 新模型更优 → 部署上线
   └─ 新模型更差 → 保留旧模型
```

### 6.3 三种学习范式

| 范式 | 范围 | 触发 |
| --- | --- | --- |
| 单点学习 | 单个老人 | 家属反馈误报/漏报 |
| 群体学习 | 整个社区 | 同一机构连续 5 次真诈骗 |
| 跨域迁移 | 跨社区 | 新社区出现新模式 |

### 6.4 Data Network Effect

> **Learn 模块驱动的数据飞轮**:
>
> 更多老人使用 → 更多画像 + 知识图谱
> → 更准的 baseline + 更准的 vulnerability + 更准的阶段判断
> → 更少的误报 + 更早的预警 + 更准的资源调度
> → 更多家属信任 + 更多物业/政府采购
> → 更多老人使用(循环)

### 7.3 评价指标体系

| --- | --- | --- |

## 第八章:商业模式与四个 Network Effects

                        ┌────────────────────────┐

   └────────┘ └────────┘   └──────────┘   └──────────┘ └────────┘

### 8.2 四个 Network Effects(真正护城河)

> **真正护城河不是「谁付钱」,而是「为什么别人复制不了」**。

| Network Effect | 含义 | 不可复制性 |
| --- | --- | --- |
| **Data Network Effect** | 老人画像 / 行为基线 / 反馈结果 | 需要长期积累,新进入者无数据 |
| **Knowledge Graph Network Effect** | 机构 / 访客 / 活动 / 投诉网络 | 需要时间 + 多方数据汇聚 |
| **Scheduling Network Effect** | 资源信任度 / 响应历史 / 调度经验 | 需要真实调度数据,冷启动难 |
| **Deployment Scale Effect** | 小区覆盖 / 协同节点 / 群体防护 | 需要商务拓展 + 部署经验 |

> **这四个 Network Effects 是新进入者短期内无法复制的真正护城河。**

### 8.3 与「传统商业模式」的差异

| 维度 | 传统商业模式 | **Network Effects 视角** |
| --- | --- | --- |
| 关注 | 谁付钱 | **为什么别人复制不了** |
| 护城河 | 客户关系 | **网络效应** |
| 增长模型 | 线性(卖一个赚一个) | **指数(网络越大越有价值)** |
| 防御性 | 中 | **极高** |

## 第九章:为什么最终演化为 Risk OS?

> **IRMS 不是反诈平台,而是 Risk OS 的第一个落地核心。反诈只是第一个插件。**

### 9.1 抽象升维

```
当前:   IRMS = 反诈系统
未来:   Risk OS = 家庭智能风险操作系统

Risk OS Core(核心不变)
   ├── Perceive → Understand → Memory → Reason
   ├── Risk Evolution → Decision → Resource Scheduling
   └── Action → Feedback → Learn

Risk Plugin(插件可替换)
   ├── 诈骗插件(当前 MVP)
   ├── 跌倒插件(Phase 2)
   ├── 走失插件(Phase 2)
   ├── 火灾/燃气插件(Phase 3)
   ├── 失联插件(Phase 3)
   ├── 健康监测插件(Phase 3)
   └── ……
```

### 9.2 核心架构的抽象升维 ★

> **这一节是 Risk OS 真正成立的架构基础。**

| 层级 | 当前实现 | **未来抽象** |
| --- | --- | --- |
| **决策层** | Rule / ML / LLM | **Policy**(Rule/ML/RL/LLM 都是 Policy 实现,架构不变) |
| **记忆层** | World Model + KG | **Semantic / Episode / Profile / Procedural Memory** |
| **推理层** | Evidence Chain(线性) | **Graph Reasoning**(图搜索,第二版) |
| **世界模型** | 四张表 | **World State(Entities/Relationships/Events/Timeline/Risk State)** |
| **调度层** | 5 维调度 | **5 维调度 + 多目标优化**(可拓展到任何资源) |
| **学习层** | 反馈驱动 | **Multi-task Learning**(同时服务多个插件) |

### 9.3 为什么这是合理的演进

- **核心能力不变**:感知、推理、记忆、决策、调度、执行、反馈、学习 —— **任何风险场景的通用能力**。
- **插件可替换**:换不同的感知模型 + 不同的标签体系 + 不同的干预策略,就能服务新场景。
- **数据资产复用**:World State、Memory、协同网络,在新场景中 **直接复用**,无需重建。

### 9.4 单一反诈平台 vs Risk OS

| 维度 | 单一反诈平台 | **Risk OS** |
| --- | --- | --- |
| 业务边界 | 反诈 | **家庭全场景风险** |
| 核心架构 | 反诈专用 | **通用风险操作系统** |
| 扩展方式 | 推翻重建 | **插件替换** |
| 数据资产 | 反诈垂直 | **跨场景复用** |
| 商业天花板 | 反诈市场 | **万亿级家庭风险市场** |

### 9.5 路线图

```
Phase 1(MVP · 3 个月)         反诈插件 + IRMS 核心
Phase 2(6 个月)              + 跌倒 / 走失插件 + LLM Reasoning
Phase 3(12 个月)             + 健康 / 火灾 / 燃气插件
最终                          Risk OS 家庭智能风险操作系统
```

## 第十章:产品哲学与总结

### 10.1 一句话产品哲学

> **AI 不是决策者,而是「帮助老人相信正确的人」+「调度最优响应资源」。**

### 10.2 我们到底在做什么

```
不是:  AI 识别诈骗 → 报警 → 结束
而是:  持续感知 → 世界知识查询 → 风险阶段判断
       → 决策 Policy → 调度老人最信任的资源
       → 通过信任桥梁传达判断
       → 反馈驱动学习 → 画像升级 → 系统更懂这位老人
```

### 10.3 为什么这条路径成立

| 问题 | 我们的回答 |
| --- | --- |
| 老人不信 AI | Trust Enhancement(可解释 + 第三方验证 + 长期陪伴) |
| 报警后没人来 | Resource Scheduling(动态调度 + 升级超时) |
| 每次都从零判断 | World State + Knowledge Graph(查询世界知识) |
| 系统不会变聪明 | Learn 闭环(人工审核 + 离线重训 + 数据飞轮) |
| 只能做反诈 | Risk OS 抽象升维(同一套核心,多插件复用) |

### 10.4 真正的护城河

> 不是某个模型,而是 **四个 Network Effects**:
> **Data · Knowledge Graph · Scheduling · Deployment Scale**
> 这是新进入者短期内无法复制的真正护城河。

### 10.5 最后的判断

> **这个项目的最大价值,不是某个 AI 模型,而是 IRMS → Risk OS 的整套架构框架。**
>
> 它为未来扩展到反诈之外的家庭风险管理提供了 **统一的技术基础**。
>
> 从比赛角度,可以冲国奖。
> 从产品角度,银龄盾 Risk OS 可以成为家庭智能风险操作系统。

### B.1 风险演化阶段识别(MVP 规则版)

```python
def identify_stage_rule_based(event, elder):
    count = elder.recent_visitor_count
    keywords = event.speech.keywords
    tags = event.tags

    if count == 0:
        return 'CONTACT', 20
    if count == 1 or '礼品' in keywords or '免费' in keywords:
        return 'TRUST_BUILDING', 35
    if count >= 3 or '不要告诉孩子' in keywords:
        return 'MANIPULATION', 50
    if ('稳赚' in keywords or '内部' in keywords) and '保密' in keywords:
        return 'INDUCTION', 65
    if tags.get('elder_card') or tags.get('qr_scan'):
        return 'TRANSACTION', 82
    if tags.get('transferred'):
        return 'SCAMMED', 97
    return 'UNKNOWN', 30
```

def schedule_resources_mvp(risk_event):
    schedule = []

### B.3 增量式证据链构建

```python
def build_evidence_chain(event, elder, world):
    chain, score = [], 0

    # 信号层
    if event.tags.get('stranger_streak', 0) >= 3:
        chain.append(('陌生访客连续三天来访', 15, 'signal'))
        score += 15
    if event.tags.get('elder_card'):
        chain.append(('老人今天第一次拿出银行卡', 25, 'signal'))
        score += 25
    if '不要告诉孩子' in event.speech.keywords:
        chain.append(('检测到「不要告诉孩子」关键词', 30, 'signal'))
        score += 30

    # 画像层(Profile Memory)
    if elder.vulnerability_score > 0.6:
        chain.append(('画像:老人易受骗程度偏高', 10, 'profile'))
        score += 10

    # 知识层(Knowledge Graph)
    org = world.visitor_to_org.get(event.tags.get('visitor_id'))
    if org and org.complaint_count >= 5:
        chain.append((f'知识图谱:{org.name} 历史投诉 {org.complaint_count} 次', 20, 'knowledge'))
        score += 20

    return chain, score
```
