# 银龄盾 IRMS · 定稿版

> **这不再是一个反诈骗系统,而是一套完整的智能风险管理系统**
> **(Intelligent Risk Management System, IRMS)**。
>
> 它把诈骗视为 **连续演化过程**,把老人、访客、活动、机构都纳入 **统一世界模型**,
> 通过 **资源调度** 而非简单推送完成干预,通过 **主动学习** 持续自我进化。
>
> —— 本文档是面向答辩的定稿版,正文聚焦架构与价值主线,
> 详细数据模型、算法伪代码与扩展设计放在附录。

---

## 产品哲学

**AI 不是决策者,而是「帮助老人相信正确的人」+「调度最优响应资源」。**

```
不是:  AI: "这是诈骗。"
而是:  AI: "建议联系您的儿子确认。"
       或
       AI: "社区工作人员已经帮您核验,该活动不存在备案。"

不是:  AI: "已通知家属。"
而是:  AI: 调度算法 → 家属未响应 → 升级社区 → 社区未响应 → 升级物业 → 升级 110。
```

防诈骗真正的难点,从来不是「识别」,而是 **让老人愿意接受帮助 + 让合适的人在合适的时间介入**。
所以 IRMS 的核心不是「识别诈骗」,而是 **「风险管理」+「资源调度」**。

## 项目定位(一句话贯穿)

> **银龄盾 IRMS 是一个持续进化的智能风险管理系统,具备 10 个能力模块的循环感知与决策能力,维护一份统一的「世界模型与知识图谱」,通过「资源调度」而非简单推送完成干预。**

## 三、IRMS 架构总览

### 3.1 10 个能力模块的循环

```
                  ┌──────────────────────────────────────┐
                  │   Memory(世界模型与知识图谱)         │
                  │   Elder / Visitor / Activity / Org   │
                  │   ↑↓ 持续读写                        │
                  └──────────────────────────────────────┘
                                ↑↓
        ┌─────────────────────────────────────────────────────┐
        │                                                     │
        │   Perceive(感知)              → 风险发现             │
        │        ↓                                            │
        │   Understand(理解)            → 风险证据             │
        │        ↓                                            │
        │   Memory(长期记忆)            → 知识查询             │
        │        ↓                                            │
        │   Reason(推理)                → 风险解释             │
        │        ↓                                            │
        │   Risk Evolution(风险演化)    → 阶段判断             │
        │        ↓                                            │
        │   Decision(智能决策)          → 干预方案             │
        │        ↓   Rule + ML + LLM                          │
        │   Resource Scheduling(资源调度) → 选谁、顺序    [Agent]│
        │        ↓                                            │
        │   Action(协同干预)            → 多通道执行           │
        │        ↓   + Trust Enhancement                      │
        │   Feedback(结果反馈)          → 闭环数据             │
        │        ↓                                            │
        │   Learn(主动学习)             → 规则/画像/模型升级 [Agent]│
        │                                                     │
        │        ↓ 回到 Perceive(世界模型持续更新)            │
        └─────────────────────────────────────────────────────┘
```

### 3.2 能力模块与 Agent 特征(术语收敛)

> **重要说明**:IRMS 由 **10 个能力模块** 组成。**这 10 个模块在数据流上都是处理节点,但只有其中 3 个具备完整的 Agent 特征** —— 自主目标、规划能力、与其他模块的协商能力。

| 模块 | 性质 | Agent 特征说明 |
| --- | --- | --- |
| Perceive | **能力模块** | 单纯处理节点,无自主决策 |
| Understand | **能力模块** | 单纯处理节点,无自主决策 |
| Memory | **能力模块** | 被动读写,无自主决策 |
| Reason | **能力模块** | 单纯推理,无自主决策 |
| Risk Evolution | **能力模块** | 阶段识别,无自主决策 |
| Decision | **能力模块** | 输出干预方案,但 **不直接执行** |
| **Resource Scheduling** | ✅ **Agent** | **自主目标**:在约束下选最优资源;**规划**:多级响应链;**协商**:与可达性、信任、成本约束协商 |
| Action | **能力模块** | 单纯执行通道 |
| Feedback | **能力模块** | 单纯反馈采集 |
| **Learn** | ✅ **Agent** | **自主目标**:最大化长期准确率;**规划**:决定何时重训、调参、画像升级;**协商**:与反馈、Memory 协商 |

> **这一定义是为了在答辩时被追问「这些 Agent 怎么通信、用什么框架」时能严谨回答**:绝大多数模块是 Pipeline 节点,只有 Scheduling 和 Learn 两个模块具备完整 Agent 特征,Decision 模块介于二者之间(有规划但执行权交给 Scheduling)。

### 3.3 协同网络 vs 四端部署

> 两个层次:**协同网络**回答「谁共享风险」,**四端部署**回答「物理部署在哪」。

## 六、How(智能层)—— 10 个能力模块

> **每个模块给出:职责、输入、输出、与其他模块的关系**。详细数据模型、伪代码、算法放附录。

### 6.1 Perceive(感知)

- **职责**:眼睛和耳朵,采集事实。
- **关键设计**:全部带 `timestamp + source`,异常显式上报,不做判断。

### 6.2 Understand(理解)

- **职责**:把事实变成结构化标签(多模态)。

### 6.3 Memory(长期记忆)

- **职责**:维护世界模型与知识图谱,提供知识查询接口。
- **详见第八章**。

### 6.4 Reason(推理)

- **职责**:给出 **可解释的增量式证据链**。
- **详见第十一章**。

### 6.5 Risk Evolution(风险演化)

- **职责**:判断老人「走到了诈骗第几阶段」。
- **详见第九章**。

### 6.6 Decision(智能决策)

- **职责**:决定「该不该干预」。
- **风险引擎三层**:Rule + ML + LLM(MVP 实现 Rule + ML 两层)。
- 三层职责:RULE 毫秒级强信号 / ML 概率化 / LLM 可解释解释。

### 6.7 Resource Scheduling(资源调度) —— ✅ Agent

- **职责**:在多约束下选最优资源、按顺序、超时升级。
- **详见第十章**。
- **Agent 特征**:自主目标 + 多约束规划 + 与可达性/信任协商。

### 6.8 Action(协同干预)

- **职责**:多通道执行 + Trust Enhancement 注入。
- 通道:本地语音 / 微信 / 短信 / 社区 / 录像。

### 6.9 Feedback(结果反馈)

- **职责**:采集每一次干预的反馈(成功/失败、误报/漏报、家属/社区反馈)。

### 6.10 Learn(主动学习) —— ✅ Agent

- **职责**:反馈驱动规则、画像、模型升级。
- **详见第十二章**。
- **Agent 特征**:长期准确率最大化 + 决定何时重训 + 与 Memory 协商画像升级。

## 八、世界模型与知识图谱(Memory 模块)

### 8.1 为什么需要世界模型

多数 AI 系统每次都 **重新判断**,不利用已有知识。
IRMS 维护一份 **世界模型**,任何事件都是「查询世界知识」,而不是「从零分析」。

### 8.2 四类画像

| 画像 | 关键字段 | 价值 |
| --- | --- | --- |
| **老人画像** | 行为基线、家庭关系、易受骗程度、被骗史、健康、性格、数字能力 | 偏离检测、个性化阈值 |
| **访客画像** | 出现频率、停留时长、是否换装、是否同行 | 陌生关系识别 |
| **活动画像** | 地点、举报次数、是否备案、收费、历史参与人数 | 群体风险识别 |
| **机构画像** | 名字、联系电话、关联二维码、投诉次数、关联活动/访客 | 团伙识别 |

> **详细字段定义、JSON Schema、知识图谱查询流程见附录 A**。

### 8.3 知识图谱查询示例

```
事件:陌生访客到访(visitor_unknown_001)
   ↓
Memory 查询:该访客所属机构?
   ↓
命中:org_suspicious_001(历史投诉 8 次)
   ↓
加权:机构风险 → +20
   ↓
反馈给 Reason 模块,作为证据链一环
```

## 九、风险演化模型(Risk Evolution 模块)

### 9.1 诈骗六阶段

| 阶段 | 典型信号 | 风险分 | 干预策略 |
| --- | --- | --- | --- |
| 1 接触 | 第一次陌生号码、上门 | 20 | 记录画像 |
| 2 建立信任 | 第二次上门、关心话术、赠送小礼品 | 35 | 提醒家属 |
| 3 长期情感操控 | 连续 3+ 天到访、「不要告诉孩子」 | 50 | 推送家属视频 |
| 4 诱导 | 提出「稳赚」「内部」、要求保密 | 65 | 启动资源调度 |
| 5 交易 | 让带银行卡、扫码付款 | 82 | 紧急多通道干预 |
| 6 被骗 | 老人已付款 | 97 | 应急 + 复盘 + 学习 |

### 9.2 动态增长曲线

```
风险
100 ┤                                      ● ←被骗
    │                                  ●
 80 ┤                              ●       ←交易
    │                          ●
 60 ┤                      ●               ←诱导
    │                  ●
 40 ┤              ●                       ←操控
    │          ●
 20 ┤      ●                               ←建立信任
    │  ●                                   ←接触
  0 ┼────────────────────────────────────
    第1次 第2次 第3次 第4次 第5次 第6次
```

### 9.3 阶段识别对干预的指导意义

> 阶段 1-2:**记录为主**,不升级干预(否则噪声大)。
> 阶段 3-4:**资源调度启动**,选最优响应资源。
> 阶段 5-6:**紧急多通道协同**,所有节点联动。

> **阶段识别算法伪代码见附录 B.1**。

## 十、资源调度(Resource Scheduling · ✅ Agent)

### 10.1 为什么必须做资源调度

> **多数 AI 系统止步于「通知家属」,银龄盾要做的是「调度最优响应」**。
> 晚上十点、儿子国外、社区未响应、物业未响应、110 —— 这才是真实场景。

### 10.2 资源池(8 节点)

| 响应级 | 资源 | 适用 |
| --- | --- | --- |
| 一级(快速) | 家属(本地)、邻居、物业 | 5min 内到场 |

## 十六、答辩统一表述

> 我们构建的不是一个反诈 AI 功能,而是一个 **智能风险管理系统(IRMS)** —— 银龄盾。
>
> 它把诈骗视为 **连续演化过程**,而不是一次性事件。它维护一份统一的 **世界模型与知识图谱**(老人、访客、活动、机构),让所有判断都基于已有知识,而非从零分析。它通过 **资源调度** 而非简单推送完成干预,动态选择「谁」介入、按「什么顺序」、超时如何「升级」。它通过 **主动学习** 持续自我进化,每一次干预都让系统更准。
>
> IRMS 拥有 **10 个能力模块**(Perceive / Understand / Memory / Reason / Risk Evolution / Decision / Resource Scheduling / Action / Feedback / Learn),其中 Resource Scheduling 与 Learn 两个模块具备完整 Agent 特征。
>
> 系统部署在 **Home + Mobile + Family + Community** 四端,通过 **8 节点协同网络** 共享风险。
>
> 我们的产品哲学是:**AI 不是决策者,而是「帮助老人相信正确的人 + 调度最优响应资源」**。
>
> 我们的核心壁垒不是某个模型,而是 **四种长期资产**:统一的 **世界模型与知识图谱**、反馈驱动的 **主动学习闭环**、8 节点共享的 **协同防护网络**、复用现有设备的 **部署成本优势**。这四件事,竞品难以复制。
>
> 第一版我们没有做 AI 换脸、AI 拟声、LLM Reasoning,因为两个月做不完。**我们只做一件事:让一个独居老人,在被骗之前 30 分钟,被合适的人在合适的时间拦下来**。在我们的实验中,这一时间差是普通方案的近 10 倍。
>
> 这不是一个比赛作品,而是一个 **数字守护平台** —— 用一个持续进化的 IRMS,守护每一位独居老人。

```python
def identify_stage(event, elder_profile, world):
    contact_count = elder_profile.recent_visitor_count

        return Stage.TRUST_BUILDING, 35, '提醒家属'
    if contact_count >= 3 and has_secret:
        return Stage.MANIPULATION, 50, '推送家属视频'
    if has_secret and ('稳赚' in event.speech or '内部' in event.speech):
        return Stage.INDUCTION, 65, '启动资源调度'
    if has_card or has_payment:
        return Stage.TRANSACTION, 82, '紧急干预'
    if has_payment and elder_profile.suspicious_outcome:
        return Stage.SCAMMED, 97, '应急+复盘'
```

### B.2 资源调度算法

```python
def schedule_resources(risk_event, elder, world):
    candidates = []
    for resource in RESOURCE_POOL:
        score = (
            reachability(resource) * 0.30 +
            (1 / response_time(resource)) * 0.25 +
            capability_match(resource, risk_event.type) * 0.20 +
            trust_score(resource, elder) * 0.20 +
            (1 - cost_score(resource)) * 0.05
        )
        candidates.append((resource, score))

    candidates.sort(key=lambda x: -x[1])

    schedule = {
        'primary':   (candidates[0], 5*60),    # 5 分钟超时
        'secondary': (candidates[1], 15*60),   # 15 分钟超时
        'tertiary':  (candidates[2], 30*60),   # 30 分钟超时
        'fallback':  (candidates[3], 60*60),   # 60 分钟超时
    }
    return schedule
```

```python
def build_evidence_chain(event, elder_profile, world):
    chain = []
    score = 0

    # 信号层
    if event.tags.get('stranger_visit_streak', 0) >= 3:
        chain.append(('陌生访客连续三天来访', 15, 'signal'))
        score += 15
    if event.tags.get('elder_card'):
        chain.append(('老人今天第一次拿出银行卡', 25, 'signal'))
        score += 25
    if '不要告诉孩子' in event.speech.keywords:
        chain.append(('检测到「不要告诉孩子」关键词', 30, 'signal'))
        score += 30

    # 画像层
    if elder_profile.vulnerability_score > 0.6:
        chain.append(('画像:老人易受骗程度偏高', 10, 'profile'))
        score += 10

    # 知识层
    org = world.visitor_to_org.get(event.tags.get('visitor_id'))
    if org and org.complaint_count >= 5:
        chain.append((f'知识图谱:{org.name} 历史投诉 {org.complaint_count} 次', 20, 'knowledge'))
        score += 20

    confidence = min(0.99, 0.5 + score * 0.005)
    return EvidenceChain(items=chain, total_score=score, confidence=confidence)
```
