# 架构设计



> **核心定位(贯穿全文的一句话)**
>
> **我们不是做一个诈骗识别系统,而是构建一个面向老年人的诈骗风险数字孪生。**
>
> 系统的核心不是「某一次诈骗事件」,而是一个 **持续维护的、动态更新的、属于每一位老人的风险画像**。
> 所有感知、所有推理、所有干预、所有学习,都围绕这个画像展开。
> 从「事件识别」到「持续智能体」,这是 AI 系统从单点工具向数字孪生演进的必然方向。

---

## 〇、总框架(项目灵魂 · 文档第一页)

> **这句话必须贯穿全文**:我们做的是 **风险管理(Risk Management)**,不是 **风险识别(Risk Identification)**。

```
                老年诈骗风险数字孪生(Risk Digital Twin)
                       ↑          ↓ (读)   (写)
                       │          │
┌──────────────────────────────────────────────────────────────┐
│                                                              │
│   Perceive(感知)         →  风险发现                         │
│        ↓                                                 [Agent 1]│
│   Understand(理解)       →  风险证据                         │
│        ↓                                                 [Agent 2]│
│   Predict(预测)          →  风险预警                         │
│        ↓                                                 [Agent 3]│
│   Reason(推理)           →  风险解释                         │
│        ↓                                                 [Agent 4]│

**主线六要素**:风险发现 → 风险证据 → 风险解释 → 风险干预 → 风险响应 → 风险反馈。

## 一、边界宣言(MVP · 第一版只做什么)

> **这是评委最看重的工程思维 —— 不是「能做什么」,而是「敢不做什么」**。

### 1.1 我们 **做** 的

| 维度 | 第一版范围 |
| --- | --- |
| **场景** | 居家上门诈骗、社区活动诈骗、AI 拟声诈骗(三大类) |
| **视觉** | 3 类:陌生人识别、访客停留检测、老人情绪识别 |
| **语义** | 5 类:投资、养老、公安、保密、转账 |
| **风险评估** | 1 套三层风险引擎(规则 + ML + LLM) |
| **闭环** | 1 条:风险发现 → 干预 → 反馈 → 学习 |
| **部署** | 萤石平台 + 老人手机 + 家属端 + 社区端 |

### 1.2 我们 **不做** 的(明确放弃)

| 维度 | 暂不做 |
| --- | --- |
| ❌ | OCR 通用识别(暂只针对合同、传单关键词) |
| ❌ | AI 换脸检测(下一版) |
| ❌ | LLM 通用对话(LLM 仅用于解释与推理,不用于客服) |
| ❌ | 通用多模态(暂只做视频 + 音频 + 通信) |
| ❌ | 商业化推广工具 |
| ❌ | 医疗级健康监测 |

> **MVP 第一版只服务一个核心场景:让一个独居老人,在他被骗之前 30 分钟,被拦截下来。**

### 1.3 边界与评委沟通的话术

> 「很多同学想做 AI 万能识别系统,我们反而想清楚了我们 **不做什么**。第一版我们只做三类视觉、五类语义、一个风险评分、一个闭环。这看起来少,但每一项都做到 90% 准确率,比做一个什么都识别但什么都 60% 的系统更有价值。」

> **由第三位队友主导。这一层回答:系统到底部署在哪里?**

### 2.1 四端部署

```
                     ┌──────────────────┐
                     │   Community      │
                     │  (社区/物业)      │
                     └────────┬─────────┘
                              ↑
                              │ Community Agent
                              │

   │   Family     │ ←  │   AI Center      │ →  │  Elder Phone │
   │   (家属端)   │    │ (AI Risk Agent) │    │  (Mobile)    │
   └──────────────┘    └──────┬───────────┘    └──────────────┘
         Family Agent          │                  Mobile Agent
                              ↓
                     ┌────────┴─────────┐
                     │  Hikvision Camera │
                     │  (Home Edge)     │
                     └──────────────────┘

### 2.2 萤石平台的真实接入(不是摆设)

> 很多队伍写「基于萤石」,其实没有任何调用。我们是 **真正调用萤石开放平台**。

```
萤石设备
  ↓ RTSP / EZUI / Open API
视频流 + 事件流(陌生人、访客停留、门铃触发)
  ↓
Home Agent(本地 / 云端协同推理)
  ↓ 结构化事件
AI Risk Agent(中央推理与决策)
  ↓ 风险评估 + 干预指令
三端联动(家属 / 社区 / 老人)
```

| 萤石能力 | 我们的使用 | 对应 Agent |
| --- | --- | --- |
| RTSP 视频流 | 实时拉流 + 视觉推理 | Perceive Agent |
| 事件订阅(陌生人/门铃) | 触发 Agent 工作流 | Perceive Agent |
| 云存录像 | 关键片段自动切片归档 | Memory Agent |
| 设备管理 SDK | 老人多设备统一纳管 | Home Agent |
| 推送通道 | 风险预警触达家属/社区 | Action Agent |

### 2.3 四 Agent 分布式架构

> **不是「四个端」,而是「四个 Agent」** —— 每个端都是一个独立 Agent,各有自治能力。

| Agent | 载体 | 自治能力 | 受 AI Risk Agent 调度 |
| --- | --- | --- | --- |
| **Home Agent** | 萤石 | 陌生人检测、情绪识别、关键词提取、本地告警 | ✅ |
| **Mobile Agent** | 老人手机 | 通信监听、App 分析、GPS、外出提醒 | ✅ |
| **Family Agent** | 家属 App | 远程视频、一键决策、证据查看 | ✅ |
| **Community Agent** | 社区平台 | 网格员介入、群体预警、应急流程 | ✅ |

**关键洞察**:
> 多数 AI 系统是「集中式」—— 一个大脑,所有摄像头往这一个大脑送。
> 我们的设计是「**分布式 Agent + 中央协同**」—— 每个端都能自治感知,中央负责综合推理与跨端协同。
> 即使中央 AI 临时不可用,各端 Agent 仍能本地应急。

### 2.4 空间维度:家里 + 家门外

> 老人有两个世界。多数项目只覆盖家里,我们覆盖两个。

| 空间 | 风险类型 | 感知来源 |
| --- | --- | --- |
| **家里** | 陌生人上门、推销、保健品送货、情绪异常 | Home Agent(萤石) |
| **家门外** | 会销、养老讲座、免费鸡蛋、广场、AI 拟声电话 | Mobile Agent(老人手机) |

> 标签不是模型的一次性输出,而是 Risk Digital Twin 的持久属性。

## 四、How(智能层)—— AI Risk Agent 七大 Agent

> **本人主导。这一层回答:AI 如何智能决策?**
> **不再只是「分层」,而是真正的「Multi-Agent System」**。
> 每一个 Agent 是一个有状态的、有目标的、可独立部署的服务。

### 4.1 七个 Agent 总览

| Agent | 输入 | 输出 | 读写 Risk Digital Twin |
| --- | --- | --- | --- |
| **Perceive Agent** | 萤石视频流、手机事件、GPS | 结构化原始事件 | 写:事件流 |
| **Understand Agent** | 原始事件 | 多模态标签 | 写:标签属性 |
| **Predict Agent** | 标签 + 历史画像 | 趋势预测 + 偏离度 | 写:预测属性 |
| **Reason Agent** | 标签 + 预测 + 画像 | 因果链 + 风险来源 | 写:解释属性 |
| **Decision Agent** | 因果链 + 画像 | 风险等级 + 干预方案 | 读 + 写:决策属性 |
| **Action Agent** | 干预方案 + Trust 策略 | 多通道执行 + 反馈 | 写:响应日志 |
| **Memory Agent** | 所有 Agent 写入 + 反馈 | **更新风险数字孪生** | 核心读写 |

**Agent 间协作**:

```
Perceive ──→ Understand ──→ Predict ──→ Reason ──→ Decide ──→ Act
    │            │            │          │          │        │
    └────────────┴────────────┴──────────┴──────────┴────────┘
                                  ↓
                          Memory Agent
                          (Risk Digital Twin)
                                  ↓
                          所有 Agent 读取画像
```

> **Memory Agent 不是旁观者,而是中枢** —— 所有 Agent 都在持续读写风险数字孪生。

---

### 4.2 Perceive Agent(感知 Agent)

**目标**:风险发现。

**输入**:萤石视频流、拾音器音频、手机事件、GPS、门磁。
**输出**:结构化原始事件流。

```json
{
  "event_id": "evt_20260630_0915",
  "source": "hikvision_living_room",
  "timestamp": "2026-06-30 09:15:23",
  "type": "visitor_entered",
  "raw": {
    "image_url": "...",
    "duration": 0
  }
}
```

**关键设计**:
- 全部输出带 `timestamp` + `source`,可追溯。
- 异常信号(掉线、采集失败)必须显式上报。
- 不做判断,只采集事实。

---

### 4.3 Understand Agent(理解 Agent)

**目标**:风险证据。

**输入**:Perceive Agent 输出。
**输出**:多模态标签。

```json
{
  "event_id": "evt_20260630_0915",
  "tags": {
    "person":   { "age": "~45", "gender": "male", "uniform": false, "carry": ["宣传袋"] },
    "emotion":  { "elder_stress": 0.83 },
    "speech":   { "keywords": ["投资", "养老金", "稳赚"], "intent": "推销" }
  }
}
```

**核心模型**(2026 年水平的 AI 选型):

| 任务 | 模型 | 备注 |
| --- | --- | --- |
| 视觉检测 | YOLOv8 / RT-DETR | 实时 |
| 行人重识别 | OSNet / ReID | 陌生人 vs 已知 |
| 行为识别 | SlowFast / VideoMAE | 站立/倒地/急促 |
| 情绪识别 | EmoNet / FER | 紧张/兴奋/恐惧 |
| 语音转写 | Whisper Large-v3 | 多方言 |
| 关键词 + 意图 | LLM (Qwen / GPT) | 5 类关键词 + 意图分类 |
| 声纹识别 | ResNet / ECAPA | 老人本人 vs AI 拟声 |

---

### 4.4 Predict Agent(预测 Agent)

**目标**:风险预警(事前)。

**输入**:标签 + 历史画像。
**输出**:趋势预测 + 偏离度。

```json
{
  "elder_id": "elder_001",
  "trend":       { "horizon": "next_24h", "rising": true },
  "target_prob": 0.86,
  "deviation":   { "baseline_risk": 0.12, "current_risk": 0.74, "delta": 0.62 },
  "predicted_type": ["投资诈骗", "上门会销"]
}
```

**预测范式**:

| 范式 | 信号 | 输出 |
| --- | --- | --- |
| 趋势预测 | 最近 7 天每天 10+ 陌生电话 | 正在被围猎 |
| 关系预测 | 陌生人连续 7 天上门 | 正在建立信任 |
| 行为预测 | 老人从不参加讲座 → 突然去会销 | 行为强偏离 |

---

### 4.5 Reason Agent(推理 Agent)

**目标**:风险解释(可解释)。

**输入**:标签 + 预测 + 画像。
**输出**:因果链 + 风险来源占比。

```json
{
  "elder_id": "elder_001",
  "chain": [
    "异地陌生号码呼入",
    "通话持续 42 分钟(异常)",
    "电话含「投资」「养老金」关键词",
    "陌生人连续 3 天上门(行为异常)",
    "老人近期频繁外出(行为偏离)",
    "老人独居(无即时干预能力)"
  ],
  "score_breakdown": {
    "电话信号":    35,
    "访客信号":    25,
    "行为偏离":    20,
    "历史趋势":    10,
    "环境风险":    10
  },
  "confidence": 0.92
}
```

**关键设计**:
- 这一层是 **LLM Reasoning 的主战场** —— 用 LLM 把多源证据串成可读因果链。
- 每条证据可追溯到原始 `source`。
- 这是 Trust 层「可解释预警」的依据来源。

---

### 4.6 Decision Agent(决策 Agent · 风险引擎三层)

**目标**:风险干预决策。

> **这是用户特别强调的升级点 —— 风险引擎必须从「加权打分」升级为「Rule + ML + LLM 三层决策」**。

#### 三层决策架构

```
┌─────────────────────────────────────────────────┐
│  Layer 1 · Rule Engine(专家规则,毫秒级)        │
│  ─────────────────────────────────────────      │
│  银行卡 + 验证码 + 保密 → 直接高危(命中即触发) │
│  陌生号码 + 通话 > 30min → 中危                  │
│  老人独居 + 夜间外出 → 中危                      │
└─────────────────────────────────────────────────┘
                       ↓ 命中规则未触发时
┌─────────────────────────────────────────────────┐
│  Layer 2 · ML Model(机器学习,概率化)            │
│  ─────────────────────────────────────────      │
│  XGBoost / 轻量神经网络                          │
│  输入:多模态标签 + 历史画像                       │
│  输出:风险分数(0-100)+ 异常程度                 │
└─────────────────────────────────────────────────┘
                       ↓
┌─────────────────────────────────────────────────┐
│  Layer 3 · LLM Reasoning(大模型推理,解释化)     │
│  ─────────────────────────────────────────      │
│  输入:ML 分数 + 证据链 + Risk Digital Twin        │
│  输出:可解释结论 + 干预建议                      │
└─────────────────────────────────────────────────┘
```

#### Layer 1 · Rule Engine(专家规则)

**为什么需要规则**:
- **0 延迟**:某些模式必须毫秒级响应(如「验证码 + 银行卡」)。
- **0 误报**:专家共识的强信号,不需要 ML 重新学习。
- **可解释**:规则的逻辑本身就是解释。

```python
# 伪代码
RULES = [
    Rule(
        name="强信号直接高危",
        when=AND(
            keyword("验证码"),
            keyword("银行卡"),
            keyword("保密"),
        ),
        then=DECISION(level="极高", action="立即联系家属+语音提醒")
    ),
    Rule(
        name="通话异常",
        when=AND(
            is_unknown_caller(),
            duration() > 30*60  # 30分钟
        ),
        then=DECISION(level="高", action="通知家属+保存录音")
    ),
    Rule(
        name="独居老人夜间外出",
        when=AND(
            is_alone(),
            time() in ["22:00", "06:00"]
        ),
        then=DECISION(level="中", action="推送家属关注")
    )
]
```

#### Layer 2 · ML Model(机器学习)

**为什么还需要 ML**:
- 规则覆盖不到的 **弱信号组合**。
- **概率化输出**,便于阈值调优。
- **可被学习** —— Memory Agent 反馈自动再训练。

```python
# 伪代码
class RiskMLModel:
    def predict(self, features: RiskFeatures) -> RiskScore:
        # features 包含:多模态标签 + 历史画像 + 环境特征
        score = xgboost.predict(features.to_vector())
        return RiskScore(value=score, confidence=...)
```

**特征工程**:

| 特征组 | 来源 |
| --- | --- |
| 通话特征 | 号码属性、时长、频次、关键词 |
| 视觉特征 | 访客属性、停留时长、情绪 |
| 行为特征 | 外出频次、地点异常、作息偏离 |
| 画像特征 | 老人易受骗程度、社交风险、近期事件 |
| 环境特征 | 时间、是否独居、是否夜间 |

#### Layer 3 · LLM Reasoning(大模型推理)

**为什么还需要 LLM**:
- ML 给出 **数字**,LLM 给出 **解释**。
- 把数字翻译成 **人话**(给老人、家属、社区看)。
- 综合推理,处理 ML 看不出的长尾因果。

```python
# 伪代码
class LLMReasoning:
    def explain(self, ml_score, evidence, twin) -> Explanation:
        prompt = f"""
        你是一名专业的反诈分析师。
        
        【风险分数】{ml_score}
        【证据链】
        {evidence.format()}
        
        【老人画像】
        {twin.summary()}
        
        请给出:
        1. 风险结论(一句话)
        2. 推理依据(3-5 条)
        3. 干预建议(分优先级)
        """
        return llm(prompt)
```

**LLM 输出示例**:

> **风险结论**:老人当前面临 **投资诈骗高风险**,综合概率 **87%**。
>
> **推理依据**:
> ① 陌生异地号码连续呼入,通话 40 分钟(异常时长)
> ② 通话中出现「验证码」「银行卡」「安全账户」关键词(典型投资诈骗话术)
> ③ 老人近期频繁前往某酒店(会销高发地),行为基线明显偏离
> ④ 老人独居,无即时干预能力
> ⑤ 画像显示老人「易受骗程度」评分偏高
>
> **干预建议**:
> 1. **立即**:客厅音箱播放语音提醒,推送给女儿视频请求
> 2. **5 分钟内**:若老人未回应,联系邻居王阿姨上门
> 3. **30 分钟内**:若仍未响应,网格员介入

> **评委会喜欢的原因**:AI 终于不是黑盒了。

## 五、Human(交互层)—— Trust Layer

> **由第二位队友主导。这一层回答:AI 如何让人真正接受?**

### 5.1 为什么必须单列一层

> 防诈骗真正难的不是识别,而是 **让老人相信**。
> 老人被骗的核心是 **深度情感操控**,他们对「陌生人」反而建立了信任,对「AI 提醒」反而抗拒。

### 5.2 Trust 五层机制

#### ① 可解释预警(Explainable Warning)

```
不是:  "危险"
而是:  "检测依据:陌生号码 + 要求转账 + 持续 40 分钟,风险 92%"
```

#### ② 认知缓冲(Cognitive Buffer)

```
不是:  "你被骗了"
而是:  "建议您先暂停 5 分钟,系统正在联系您的女儿确认"
```

#### ③ 第三方验证(Third-Party Verification)

```
不是:  "AI 说:这是诈骗"
而是:  "已联系:女儿。她说:妈,千万别转,我 10 分钟到"
```

#### ④ 长期信任建设(Long-term Bonding)

```
每天:  天气提醒、吃药提醒、喝水提醒、睡眠报告
形式:  像家人,而非像机器
```

#### ⑤ 事后复盘(Post-incident Review)

```
事件:  骗子冒充公安,要求保密、要求转账
复盘:  帮助老人识别「冒充公检法」的套路
成长:  下次再遇到,老人能自己识别 70% 的类似话术
```

### 5.3 Trust 与 Action 的关系

| 层 | 职责 |
| --- | --- |
| **Action** | 把决策 **执行出去**(对谁说、说什么) |
| **Trust** | 让决策 **被接受**(为什么信、愿不愿意听) |

> 没有 Trust 的 Action:发了一百条提醒,老人全部忽略。
> 有 Trust 的 Action:一句话,老人立刻停下转账操作。

## 六、Risk Digital Twin(老年诈骗风险数字孪生)—— 全局核心对象

> **这是整个方案最核心的创新点。**

### 6.1 为什么必须引入「数字孪生」概念

**当前大多数 AI 系统的问题**:
- 系统处理的是「一次事件」—— 报警一次,结束。
- 没有「持续记忆」,没有「长期画像」。
- 每次都从零开始,无法个性化。

**数字孪生的好处**:
- 系统处理的是「一个老人」—— 持续维护一个动态画像。
- **有记忆**,有基线,有历史,有趋势。
- 越用越懂这位老人。

### 6.2 Risk Digital Twin 数据结构

```
elder_id: "elder_001"
│
├── 基础档案
│   ├── 人口学:年龄、性别、独居状态
│   ├── 居住地:家庭住址、社区、物业
│   └── 家属网络:女儿(异地)、邻居(本地)
│
├── 长期行为基线(Baseline)
│   ├── 作息:06:00 起夜、08:00 买菜、20:00 看电视
│   ├── 社交:广场舞友、邻居王阿姨
│   ├── 外出:菜市场、广场、社区卫生中心
│   └── 偏好:听戏曲、不喜欢甜食
│
├── 易受骗程度(Vulnerability Score)
│   ├── 静态因素:年龄、教育、收入、独居
│   ├── 动态因素:近期情绪、社交变化、健康
│   └── 历史事件:过去是否被骗过、是否识别过诈骗
│
├── 社交风险地图(Social Risk Map)
│   ├── 高频联系人:女儿、邻居、广场舞友
│   ├── 陌生接触:陌生人来电频率、上门频率
│   └── 异常关系:新建立的陌生关系
│
├── 最近异常事件(Recent Anomalies)
│   ├── 06-23:陌生号码,已忽略
│   ├── 06-26:陌生人上门,家属确认装修
│   └── 06-30:高风险预警,已劝回
│
├── 干预历史(Intervention History)
│   ├── 语音提醒:成功 5 次 / 失败 1 次
│   ├── 家属视频:成功 3 次
│   └── 社区介入:1 次
│
├── 反馈结果(Feedback Results)
│   ├── 30 天误报次数:1
│   ├── 30 天漏报次数:0
│   └── 老人信任评分:0.74
│
└── 动态风险(Dynamic Risk)
    ├── 当前等级:中
    ├── 趋势:上升
    └── 关键因子:[投资关键词频率增加,陌生人连续上门]
```

### 6.3 数字孪生如何被各 Agent 使用

| Agent | 如何使用 Risk Digital Twin |
| --- | --- |
| **Perceive Agent** | 写入新事件流 |
| **Understand Agent** | 读取历史标签,做对比 |
| **Predict Agent** | 读取 baseline,做偏离检测 |
| **Reason Agent** | 读取 vulnerability、社交风险、做综合推理 |
| **Decision Agent** | 读取干预历史、信任评分、决定干预策略 |
| **Action Agent** | 读取老人信任度,选择 Trust 策略(可解释/认知缓冲/第三方) |
| **Memory Agent** | **核心读写者**,持续维护与更新 |

### 6.4 与传统 AI 系统的对比

| 维度 | 传统 AI 系统 | 数字孪生系统 |
| --- | --- | --- |
| 处理对象 | 单次事件 | **一个持续画像** |
| 记忆 | 无 | **长期持久** |
| 个性化 | 弱 | **强(每位老人独立)** |
| 趋势感知 | 无 | **有 baseline,可做偏离** |
| 学习 | 离线再训练 | **在线持续更新** |
| 干预 | 通用策略 | **基于信任度的个性化** |

## 十、答辩统一表述(完整版 · 可直接复用)

> 我们并不是开发一个简单的防诈骗识别系统,而是构建一个面向居家养老场景的 **AI 风险智能体(AI Risk Agent)**,更准确地说,是构建一个 **面向老年人的诈骗风险数字孪生(Elder Fraud Risk Digital Twin)**。
>
> 系统的核心不是「某一次诈骗事件」,而是一个 **持续维护的、动态更新的、属于每一位老人的风险画像**。所有感知、所有推理、所有干预、所有学习,都围绕这个画像展开。
>
> 我们做的是 **风险管理(Risk Management)**,不是 **风险识别(Risk Identification)** —— 围绕 **风险发现、风险证据、风险解释、风险干预、风险响应、风险反馈** 六步主线,构建由 **七大 Agent**(Perceive / Understand / Predict / Reason / Decision / Action / Memory)协同的智能系统。
>
> 风险引擎采用 **Rule + ML + LLM 三层决策架构**,兼顾 **毫秒级响应、概率化输出、可解释结论**。
>
> 系统部署在 **Home + Mobile + Family + Community** 四端,由 **四个分布式 Agent** 自治协同,在 **家里、家门外、家属身边、社区网格** 中,同步识别、分级响应。
>
> 同时,我们特别关注老年人在深度情感操控下对技术预警的不信任问题,引入 **可解释预警、第三方验证、长期信任建设、事后复盘** 机制,使 AI 不仅能够识别诈骗,更能够让老人 **愿意接受帮助**。
>
> 我们的四位团队成员,分别回答了 **Where(部署在哪里)、What(识别什么)、How(如何决策)、Human(如何让人接受)** 四个不同层面的问题,缺一不可,共同构成一个统一的 AI Risk Agent。
