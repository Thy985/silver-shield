# 01 · 模块在系统中的定位

## 1.1 一句话定位

Home 感知模块是 SilverShield 的 **Perceive 感知** 逻辑模块在 **Home 端** 的物理实现，
专注于**家庭入口（门前）区域的实时视觉感知**，把视频流转换为**带时间戳、带来源、可追溯的
结构化访客事件（VisitorEvent）与风险证据**，上报中心，作为风险数字孪生（RiskTwin）的前端事实输入。

## 1.2 在总体架构中的位置

```
                 SilverShield 总体（风险管理六步闭环）
  ┌──────────────────────────────────────────────────────────────────┐
  │  风险发现 → 风险证据 → 风险预测 → 风险解释 → 风险干预 → 风险反馈    │
  └──────────────────────────────────────────────────────────────────┘
        ▲ Home 感知模块（本项目）落在"风险发现 / 风险证据"两端
        │
  Home 端（门前）          AI 中心                  业务服务 / 三端
  ┌────────────┐    MQTT/HTTP     ┌────────────┐   ┌──────────────────┐
  │ 摄像头取流  │ ───────────────▶ │ Understand  │   │ Spring Boot 业务  │
  │ YOLO 检测   │   VisitorEvent  │ Predict     │   │ 权限/升级/处置闭环 │
  │ 门前规则    │   + 证据引用     │ Reason/Dec  │   │ 家属端 / 社区端    │
  │ 取证采集    │ ◀─────────────── │ (Rule+ML)   │   └──────────────────┘
  └────────────┘   配置/白名单回写 └────────────┘
```

- **上游（输入）**：萤石摄像头直播流、设备状态事件（门铃/人形/上下线）。
- **本模块（处理）**：Ingestion → Detection → Analysis(规则) → Evidence → Output。
- **下游（输出）**：AI 中心的 Understand/Predict（把原始事件转标准标签、阶段预测），
  业务服务的预警升级与处置闭环；并接收中心的白名单/阈值回写。

## 1.3 模块边界（必须遵守）

| 本模块 **负责** | 本模块 **不负责** |
| --- | --- |
| 门前人员检测、停留/频次/异常时段计算 | 语音/语义意图识别（AI 成员职责） |
| 输出 5 类门前标签事件 + 取证片段 | 把"陌生访客"判定为"诈骗人员" |
| 访客轨迹片段、重复来访计数 | 多轮诈骗阶段追踪（AI 中心 Predict） |
| 设备状态、断流重连、取流安全 | 风险最终裁决、Trust 话术生成（LLM/业务） |
| Rule + ML 侧门前信号与评分输入 | 自动监听电话/读取银行 App/无授权监控 |

> 关键原则（出自架构终稿）：**标签 ≠ 结论**。"非白名单人员 + 门前异常"只是风险信号，
> 需与入户后语义、物品、历史画像关联后，才进入综合诈骗风险判断。

## 1.4 与 RiskTwin 的数据契约

本模块产出对应中心 `VisitorEvent` 数据对象：

| 字段 | 来源 | 说明 |
| --- | --- | --- |
| 访客特征 / track_id | YOLO + 跟踪 | 用于跨帧与跨次关联 |
| 进入 / 离开时间 | 检测起止 | 计算停留时长 |
| 停留时长 | 离开−进入 | 异常停留判定 |
| 重复次数 | 历史访客匹配 | 重复来访判定 |
| 家属确认标签 | 中心回写 | 白名单/已知访客 |
| 异常时段标记 | 时间规则 | 夜间/独处风险加权 |

本模块**只写自己的事件与证据**，RiskTwin 的合并、个性化阈值、阶段预测由中心完成。
