# 09 · 风险点（Risk）

## 9.1 技术风险

| # | 风险 | 影响 | 缓解（已纳入设计） |
| --- | --- | --- | --- |
| T1 | **流稳定性**：萤石 P2P/RTSP 易断流、卡顿 | 漏检、事件断裂 | `frame_source` 断流指数退避重连；`eval_stream.py` 量化重连率 |
| T2 | **延迟**：HLS 切片延迟高（已验证为 HLS） | 实时性不达标 | MVP 改用 **RTSP**（protocol=1）优先，HLS 回退 |
| T3 | **边缘算力**：1080p 全帧 YOLO 在 CPU 慢 | 掉帧、漏检 | 第一阶段用 **YOLO11n**（比 yolov8n 新、更小）；**1080p 先显式 resize 到推理分辨率再推理**（见 `detector.py`）；`fps_target=8` 抽帧；GPU 可选（`device: cuda:0`）。**P0-4 实测结论**：纯 CPU 边缘机 `yolo11n@640` 推理 ~124ms、未达实时目标（<100ms / >10FPS），故 MVP 默认 **imgsz=480（balanced）**，满足实时约束且门前场景精度足够；`640` 作 accuracy 精度模式，`416` 作 realtime 低延迟模式（`benchmark/yolo_speed.py --profile` 可复现对比）。GPU 非当前阻塞点，不为此引入。 |
| T4 | **检测准确性**：老人/背影/逆光/遮挡误检漏检 | 误报/漏报 | 固定 ROI + 轨迹/频次多帧确认；过路短时忽略；阈值可配 |
| T5 | **隐私合规**：家庭摄像头涉敏感区域 | 伦理/合规风险 | 仅覆盖自家门前；敏感区遮挡；仅高风险存片段；自动删除期 |
| T6 | **事件风暴**：高频触发刷屏 | 告警疲劳 | `CooldownGate` 同源冷却；中高风险才取证 |
| T7 | **网络到中心不可达** | 事件丢失 | 离线环形缓冲（`output.buffer`）恢复补发 |
| T8 | **时间不同步** | 证据时间戳错乱 | 统一用设备本地 Unix 秒；中心归一；建议 NTP |
| T9 | **多设备扩展** | 单进程瓶颈 | 流水线按设备隔离，后续可多进程/容器横向扩 |
| T10 | **凭证泄露** | 安全事件 | 凭证全走 `.env`（gitignore）；`prototypes/` 已忽略 |

## 9.2 算法/数据风险
