# 02 · 模块内部架构

## 2.1 设计目标

- **可运行、可测试、可复现**（MVP 底线）：不依赖真实设备也能用模拟输入跑通闭环。
- **低延迟前置预警**：把防护时间前移到"踩点/重复来访"阶段，而非等到对话或转账。
- **边界清晰**：只产标签与证据，不裁决；对外契约稳定（`06_api_contract.md`）。
- **不过度设计**：第一阶段不引入消息队列集群、不拆微服务，单进程 + MQTT 即可。

## 2.2 处理流水线（管道）

```
┌─────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌─────────┐
│ Ingestion│──▶│ Detection│──▶│ Analysis │──▶│ Evidence │──▶│ Output  │
│ 取流/重连│   │ YOLO+跟踪│   │ 门前规则  │   │ 取证采集  │   │ 事件上报 │
└─────────┘   └──────────┘   └──────────┘   └──────────┘   └─────────┘
   帧迭代        检测框          标签事件        快照/片段       VisitorEvent
                                                (+MQTT缓冲)      +证据引用
```

| 阶段 | 包 | 输入 | 输出 | 对应全局逻辑 |
| --- | --- | --- | --- | --- |
| 取流 | `ingestion` | 萤石流地址 | (ts, frame) 流 | Perceive |
| 检测 | `detection` | frame | Detection(人+track_id) | Perceive |
| 分析 | `analysis` | detections + 时间/历史 | 门前标签事件 | Perceive→Understand(部分) |
| 取证 | `evidence` | event + 帧缓冲 | 快照/片段引用 | 风险证据 |
| 上报 | `output` | PerceptionEvent | MQTT/HTTP 消息 | 风险发现→中心 |

## 2.3 与"三层风险引擎"的关系

架构终稿定义风险引擎为 **Layer1 规则 + Layer2 ML + Layer3 LLM解释**：

- **本模块内的 `analysis` = Layer1 规则 + Layer2 ML 的"门前信号"部分**：
  - Layer1 规则：强信号低延迟（尾随+强行靠近、异常时段+观察门锁）。
  - Layer2 ML：把访客频次、停留时长、出现时段等弱特征组合成风险分数（MVP 可用轻量阈值/逻辑回归，
    不强求深度模型）。
- **LLM 解释（Layer3）不在本模块、不在第一版**：由中心在已有证据上生成分角色说明。

> 即：本模块把"原始视频"压缩为"带置信度的门前标签 + 证据链片段"，把重活留给中心做语义/阶段融合。

## 2.4 门前信号 → 标签映射（MVP 第一版可实现）

| 信号 | 实现方法 | 输出标签 | 误报控制 |
| --- | --- | --- | --- |
| 人员进入门前 ROI | 目标检测 + 固定 ROI | 普通/待核验来访 | 过路短时事件忽略 |
| 停留时间异常 | 进入/离开时间差 | 异常停留 | 按住宅动态阈值 |
| 重复来访 | 访客特征匹配 + 历史计数 | 重复来访 | 家属确认后归并 |
| 异常时段出现 | 时间规则 + 作息基线 | （叠加标记） | 结合快递/物业时段 |
| 反复靠近又离开 | 轨迹片段 + 区域状态 | 高风险接近 | 多次出现才升级 |
| 尾随/强行靠近 | 轨迹距离 + 门口停留 | 高风险接近 | 第一版可人工复核 |

## 2.5 关键设计取舍

- **抽帧而非全帧**：1080p 全帧 YOLO 在 CPU 上吃力，`config.ingestion.fps_target=8` 抽帧后送检测，
  兼顾实时性与算力（沿用 `prototypes/` 已验证的 FPS 基线方法）。
- **RTSP 优先于 HLS**：`prototypes/` 验证的是 HLS（protocol=2），但 HLS 切片延迟高；
  实时感知改用 RTSP（protocol=1）以降低端到端延迟，HLS 作为回退。
- **证据触发式存储**：默认只保留结构化事件；仅当触发中/高风险标签或收到中心指令时才存快照/短片段，
  满足"风险触发式隐私保护"。
- **离线缓冲**：中心不可达时事件落本地环形缓冲，恢复后补发（`output.buffer`）。

## 2.6 配置与可观测

- 所有阈值（停留/频次/异常时段/冷却）集中在 `config/default.yaml`，可经环境变量覆盖。
- 结构化日志（structlog JSON），每条事件带 `device_id` / `track_id` / `event_type`，
  便于与中心日志关联排查。
