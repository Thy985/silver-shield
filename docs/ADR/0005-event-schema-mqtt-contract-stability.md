# ADR-0005: 事件 Schema 与 MQTT 契约作为稳定对外接口

- 状态：Accepted
- 日期：2026-07-18
- 决策者：Owner
- 相关：`docs/06_api_contract.md`、`docs/07_event_schema.md`、ADR-0001

## 背景（Context）

Home 感知模块与中心（AI 分析服务 / 业务服务）之间需要一条清晰、稳定的接口。
若接口面随实现随意漂移，Home 与中心会互相耦合、联调成本高、版本一乱就互不兼容。

本模块对外产出的是"门前标签事件 + 证据引用"（见 ADR-0001），需要固定其**传输方式**与**数据结构**。

## 决策（Decision）

**把"事件 Schema"与"MQTT 传输契约"确立为受治理的稳定对外接口，任何改动需评审并升 `schema_version`。**

- **传输**：MQTT，topic 规范 `silvershield/home/{device_id}/events`，消息体为统一 Envelope
  （见 `docs/06_api_contract.md`）。
- **数据结构**：5 类 `EventType` + `EvidenceRef`（见 `docs/07_event_schema.md`），
  与中心数据对象 `VisitorEvent` / `RiskTwin` 对齐。
- **版本化**：契约字段变更必须评审 + 提升 `schema_version`，并有契约测试锁定格式。
- **不可达缓冲**：中心不可达时事件落本地环形缓冲，恢复后补发（`output.buffer`），不丢事件。

## 动机（Rationale）

- **解耦**：稳定契约让 Home 端与中心可独立演进，只要契约不破就互不影响（呼应 ADR-0001 的职责分离）。
- **可测试**：契约测试锁定事件格式/配置/规则，改动破坏格式时 CI 立刻报警，避免隐性不兼容。
- **轻量适配边缘**：MQTT 轻量、支持离线缓冲与断线重连，契合 Home 端网络不稳定的现实，
  且第一阶段"单进程 + MQTT"即可，无需消息队列集群。
- **可追溯兼容性**：`schema_version` 让中心能识别并兼容不同版本 Home 端。

## 后果（Consequences）

- ✅ 对外接口面收敛且稳定，联调/集成成本低。
- ✅ 契约破坏由测试拦截，兼容性有版本号可依。
- ✅ 断线不丢事件（本地缓冲补发）。
- ⚠️ 契约改动成本变高：需评审 + 升版本 + 更新契约测试，不能随手改字段（这是刻意的摩擦）。
- 📌 约束后续：新增事件字段优先"向后兼容扩展"；破坏性改动必须升 `schema_version` 并同步中心。

## 替代方案（Alternatives）

- **HTTP 轮询 / REST 上报**：否决（作为主路径）。实时性差、边缘断线重连与离线缓冲不如 MQTT 自然；
  可作为个别场景的辅助通道。
- **不做版本化、随实现改字段**：否决。会导致 Home 与中心版本漂移、隐性不兼容。
- **引入 Kafka / 消息队列集群**：否决（当前阶段）。过度设计，MVP 单进程 + MQTT 足够。
