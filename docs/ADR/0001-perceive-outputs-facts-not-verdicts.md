# ADR-0001: 感知模块只产"事实/标签"，不裁决"诈骗人员"

- 状态：Accepted
- 日期：2026-07-18
- 决策者：Owner
- 相关：`docs/01_module_positioning.md`、`docs/02_architecture.md` §2.3、`docs/07_event_schema.md`

## 背景（Context）

SilverShield 是"老年人诈骗风险数字孪生与协同预警系统"，全局按 7 个逻辑模块划分
（Perceive / Understand / Predict / Reason / Decision / Action / Memory）。本仓库负责其中的
**Home 感知模块**（Perceive + 门前时空异常与蹲守识别子系统），部署在 Home 端。

一个反复出现的诱惑是：既然摄像头已经能看到门前的人、能算停留时长和来访频次，
是否可以直接在 Home 端输出"这是诈骗人员 / 这是一起诈骗"的结论？

但"是否诈骗"是一个需要**入户语音语义、携带物品、受害人历史画像、跨设备时空**综合判断的问题，
门前视觉单点既无足够信息、也不该承担误判一个真人为"诈骗犯"的法律与伦理风险。

## 决策（Decision）

**本模块只输出结构化的"门前事实/标签事件"，绝不输出"诈骗人员/诈骗事件"的裁决。**

对外仅产出 5 类事件标签：

1. `visit_normal`（普通来访）
2. `visit_pending_verify`（待核验来访）
3. `abnormal_dwell`（异常停留）
4. `repeat_visit`（重复来访）
5. `high_risk_approach`（高风险接近）

每个事件携带置信度与证据引用（EvidenceRef），是否构成诈骗由**中心**综合语义/物品/历史画像判定。

## 动机（Rationale）

- **信息完备性**：诈骗判定需要门前视觉之外的多模态证据，Home 端不具备；越权裁决必然高误报。
- **风险与伦理**：把某个真人标注为"诈骗犯"存在名誉与法律风险；输出"事实标签"则是可辩护的客观描述。
- **架构解耦**：Perceive 只做"把原始视频压缩为带置信度的标签 + 证据链"，把语义/阶段融合的重活留给中心，
  两端可独立演进。
- **对齐终稿**：与《银龄盾 架构设计完善版 V2.0》一致——引擎分层、职责分离、Home 端只做前端事实采集。

## 后果（Consequences）

- ✅ 边界清晰：任何"要不要在本模块加个诈骗判定"的提议都可被本 ADR 直接否决。
- ✅ 契约稳定：对外只有 5 类标签 + 证据引用，中心接口面收敛（见 ADR-0005）。
- ✅ 可辩护：输出均为客观事实描述，规避伦理/法律风险。
- ⚠️ 代价：Home 端的"预警价值"依赖中心的融合能力；单看 Home 端事件不能直接告警"诈骗"。
- 📌 约束后续：`analysis` 层新增任何标签，必须落在"事实/风险信号"语义内，不得引入"诈骗结论"字段。

## 替代方案（Alternatives）

- **Home 端直接判定诈骗**：否决。信息不完备、误报代价高、伦理法律风险大。
- **输出连续风险分而非离散标签**：部分采纳——ML 层内部可用风险分，但**对外**仍归一化为离散标签 +
  置信度，避免中心与 Home 对"分数阈值"产生耦合。
