# ADR-0003: 检测采用 YOLO11n + 显式 resize，imgsz 配置化（默认 480）

- 状态：Accepted
- 日期：2026-07-18
- 决策者：Owner
- 相关：`docs/02_architecture.md` §2.5、`docs/09_risks.md`（T3）、`benchmark/yolo_speed.py`、
  `src/home_perception/core/config.py`（`ImgszProfile`）、PR #6 / PR #7

## 背景（Context）

门前感知需要在 Home 端（CPU、无稳定 GPU）实时检测"人"，并为后续跟踪/门前规则提供检测框。
初始假设是 **YOLO11n @ imgsz=640 可实时**。P0-4 性能基准（`benchmark/yolo_speed.py`，合成帧、
含 warmup 排除、CPU/内存采样）对该假设做了实测，目标阈值：输入 FPS ≥ 10、YOLO 推理 < 100ms、
端到端 < 300ms。

实测结果（CPU、合成帧参考值）：

| profile | imgsz | 单帧推理 | 输入 FPS | 达标 |
| --- | --- | --- | --- | --- |
| accuracy | 640 | ~124ms | ~8.1 | ❌ 不达标 |
| balanced | 480 | ~86ms | ~11.6 | ✅ 达标 |
| realtime | 416 | ~47ms | ~21.5 | ✅ 达标 |

即：**原假设被实测推翻**——YOLO11n@640 在本目标 CPU 上不满足实时。

同时，另一个诱惑是"直接把默认改成 416"或"等有了 GPU 再说"。Owner 明确否决这两条：
416 会牺牲小目标（手机等物品）检测能力，而这类物品是门前风险信号的重要来源；GPU 不是当前阻塞点，
MVP 应优化"可部署性"而非"精度上限"。

## 决策（Decision）

1. **模型**：检测采用 **YOLO11n**（ultralytics），推理前做**显式 resize**，检测框再映射回原始帧坐标。
2. **默认分辨率**：MVP 默认 **imgsz=480**（balanced）。
3. **配置化三档 profile**（不硬编码），由 `ImgszProfile` 提供：
   - `accuracy` = 640（精度模式，留给有 GPU/离线分析）
   - `balanced` = 480（**默认**，实时 + 可用精度的折中）
   - `realtime` = 416（低延迟模式，为 Tracker/ROI 预留算力，代价是小目标检测下降）
4. **解析优先级**：显式 `imgsz` > `profile` > 兜底 `balanced`。

## 动机（Rationale）

- **实测为准**：640 不达标是基准跑出来的结论，不是猜的（`docs/09_risks.md` T3 已记录）。
- **480 是折中点**：相对 640 约 1.78× 算力下降，满足 <100ms/>10FPS，同时保留比 416 更好的小目标检测。
- **配置化而非硬编码**：不同部署环境（CPU 型号、是否有 GPU、是否叠加 Tracker）需要不同档位，
  三档 profile 让部署方按需切换，避免"改一次默认值就得改代码"。
- **不等 GPU**：MVP 目标是"能在真实老人家里的普通设备上跑起来"，可部署性优先于精度上限。
- **显式 resize**：让分辨率成为可控、可基准、可复现的变量，而不是依赖框架隐式行为。

## 后果（Consequences）

- ✅ 实时目标达成：默认 480 在目标 CPU 上满足实时预警底线。
- ✅ 弹性：部署方可切 `realtime` 抢延迟、切 `accuracy` 抢精度，无需改代码。
- ✅ 决策可追溯：性能假设有基准脚本 + 参考数据支撑，后人可复跑验证。
- ⚠️ 416 档小目标（手机）检测下降，仅在明确需要低延迟且可接受该损失时启用。
- 📌 约束后续：Tracker（P0-5）等新增算力消耗后需**重跑基准**，若默认档不再达标，另开 ADR 调整而非静默改默认值。

## 替代方案（Alternatives）

- **保持默认 640**：否决。实测不达标，违背实时预警底线。
- **默认直接改 416**：否决。牺牲小目标（手机等物品）检测，损害门前风险信号来源。
- **等 GPU 再优化**：否决。GPU 非当前阻塞点，MVP 优先可部署性；且依赖 GPU 会抬高部署门槛。
- **硬编码单一 imgsz**：否决。不同部署环境需求不同，配置化三档更弹性。
- **换更大模型（YOLO11s/m）提精度**：否决。边缘 CPU 算力不允许，与实时目标冲突。
