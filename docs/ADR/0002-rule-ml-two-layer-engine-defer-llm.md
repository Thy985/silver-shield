# ADR-0002: 风险引擎采用 Rule + ML 两层，LLM 解释推迟到 v2

- 状态：Accepted
- 日期：2026-07-18
- 决策者：Owner
- 相关：`docs/02_architecture.md` §2.3、ADR-0001

## 背景（Context）

架构终稿把风险引擎定义为三层：**Layer1 规则 + Layer2 ML + Layer3 LLM 解释**。
本模块的 `analysis` 阶段需要在 Home 端（边缘设备、算力受限、无稳定 GPU）从门前信号产出标签事件。

问题是：第一版要不要把三层都做进来？尤其 LLM 解释——它能生成"分角色说明"，看起来很有卖点，
但 LLM 在边缘端要么跑不动，要么要联网调用，带来延迟、成本、隐私与稳定性问题。

## 决策（Decision）

**本模块第一版只实现 Layer1（规则）+ Layer2（ML）的"门前信号"部分；Layer3（LLM 解释）不在本模块、不在第一版。**

- Layer1 规则：强信号、低延迟（尾随 + 强行靠近、异常时段 + 观察门锁等）。
- Layer2 ML：把访客频次、停留时长、出现时段等弱特征组合成风险分数
  （MVP 用轻量阈值/逻辑回归即可，不强求深度模型）。
- Layer3 LLM：由**中心**在已有证据上生成分角色说明，推迟到 v2。

## 动机（Rationale）

- **边缘算力现实**：Home 端连 YOLO 实时都要精心调分辨率（见 ADR-0003），没有余量跑本地 LLM。
- **低延迟优先**：预警价值在于把防护时间前移到"踩点/重复来访"阶段，规则层能以最低延迟给出强信号。
- **职责归属**：语义解释属于中心的融合能力（与 ADR-0001 一致），不该由 Home 端承担。
- **不过度设计**：第一阶段先把"看得见、算得准、报得出"跑通，解释性留到有数据、有中心联动后再补。

## 后果（Consequences）

- ✅ 第一版范围可控：Home 端只需规则 + 轻量 ML，边缘可落地。
- ✅ 演进路径清晰：v2 在中心补 LLM 解释，不影响 Home 端已稳定的事件契约。
- ⚠️ 第一版缺"人话解释"：告警的可解释性依赖中心，Home 端事件本身只有标签 + 置信度 + 证据引用。
- 📌 约束后续：任何"在 Home 端接入 LLM"的提议属于跨阶段实现，需新开 ADR 并经 Owner 授权。

## 替代方案（Alternatives）

- **第一版就上本地 LLM 解释**：否决。边缘算力不足、延迟/成本/隐私不可控，属过度设计。
- **纯规则、不做 ML**：否决。频次/时长/时段等弱特征需要组合评分，纯阈值规则误报率高、不可调。
- **纯 ML、不要规则层**：否决。强信号（尾随、强行靠近）需要低延迟确定性响应，规则层不可替代。
