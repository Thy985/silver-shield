# 09 · Failure Cases（失败案例库）

> 最容易被忽略、但价值最高的资产类别。
> 每个案例都来自一次真实踩坑：**现象 → 根因 → 错误假设 → 修复 → 适用**。
> 写法不是「我当时怎么改的」，而是「未来在别的 AI 系统里，看到______症状，先怀疑______」。

## 为什么失败案例比模式更重要

模式告诉你「该怎么做」，失败案例告诉你「为什么你会做错」。
AI 系统的 bug 极少是语法错误，大多是**概念模型错误**——你以为系统在按 A 工作，其实它按 B 工作。
这类错误只有在「现象与预期严重不符」时才会暴露，而暴露时的定位路径本身就是可复制的能力。

## 收录标准

入库一个失败案例，必须满足：

1. **症状反直觉**——第一直觉指向的方向（前端？模型？配置？）是错的，真正根因在别处。
2. **根因可复用**——不是一次性笔误，而是某类系统都会遇到的概念陷阱。
3. **修复有普适原则**——拆掉后能写成一条「未来遇到 X 先做 Y」的规则。

## 持续扩充建议

每修一个跨 3 层以上才定位到的 bug，就回填一条。
格式严格使用下方四类标题，保持与 `04-Debug-Patterns` 的「从症状到根因」定位法互补：
debug 教你怎么**找**，failure 教你怎么**避**。
