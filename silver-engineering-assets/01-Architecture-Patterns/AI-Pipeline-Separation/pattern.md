# Pattern · AI Pipeline Separation（AI 流水线分层）

> 回答：**复杂 AI 系统应该怎么拆？**

- 来源：Silver Shield
- 类别：[01-Architecture-Patterns](../README.md)
- 阶段：三（基础架构，所有 AI 系统通用）

---

## 问题

一个「感知 → 判断 → 行动」的 AI 系统，最常犯的错误是**把各层揉在一起**：
检测代码里直接写业务判定，规则里直接调模型，展示层直接改核心模型「方便显示」。
结果是任何上层需求变动都腐蚀核心，最终不可维护、讲不清边界。

---

## 原始方案

```
摄像头 → 一大坨处理 → 网页显示「危险」
```

所有逻辑耦合在一个脚本里，模型输出即最终结论，没有中间表示。

---

## 最终方案

把系统拆成**严格自上而下依赖**的层，每层只做一件事，层间只通过结构化数据 / 接口通信：

```
Perception（检测 / 跟踪）
   ↓
Fact（结构化事实事件，无业务判断）
   ↓
Feature（特征提取，数值非判断）
   ↓
Rule（规则 / 语义，风险 = 规则命中强度）
   ↓
Decision（风险 → 动作意图，只翻译）
   ↓
Action（动作指令 → 1:1 路由）
   ↓
Presentation（人类可读叙事，只读投影）
```

**铁律**
- 事实层字段**禁止**夹带业务判断（事实是「停留 X 秒」，不是「这是嫌疑人」）。
- 特征层与规则层分离；规则消费特征，不回头读事实。
- 动作层只翻译，不做第二次风险决策。
- 展示层消费冻结边界（白名单 + 只读），不得反向改核心。

---

## 为什么这样设计

- **变更发生在正确的层**：展示层可剧烈变化，核心事实层零改动（银龄盾实证：冻结后 Dashboard 经历生命周期 / 三视图 / 真实视频 / WS 快照全变，核心一行没动）。
- **可独立验证**：每层产出结构化、可断言的中间产物（事实事件 / 风险事件 / 动作指令），每层都能单测。
- **可替换**：换模型（YOLO11n → 云端推理）只要返回同一接口即合规。

---

## 适用范围

| 领域 | 套用方式 |
|------|----------|
| 工业视觉 | 产线相机 → 缺陷检测 → 缺陷事件 → 分级规则 → 停机/告警 → 质检看板 |
| 智慧养老 | 门前摄像头 → 人体检测 → 来访事件 → 风险规则 → 通知家属 → 风险 Dashboard |
| 智慧交通 | 路口视频 → 车辆检测 → 通行事件 → 违章规则 → 抓拍 → 调度大屏 |
| 智能客服 | 用户文本 → 意图识别 → 意图事件 → 策略路由 → 转人工 → 坐席工作台 |

> 同一套骨架，换输入与语义即可。这正是「母项目」的价值：架构不用重新想。
