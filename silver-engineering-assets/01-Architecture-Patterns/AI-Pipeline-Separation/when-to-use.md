# When to Use · AI Pipeline Separation

用这个模式，当且仅当——

- [ ] 你在做一个「感知 → 判断 → 行动」类系统（视觉 / 语音 / 多模态 / Agent）。
- [ ] 系统会被**多层消费**（实时大屏 / 多角色 / 下游服务），需要稳定接口。
- [ ] 你预计**上层会频繁变动**（加视图 / 换端 / 接新消费者），但不想动核心。
- [ ] 你需要**逐层验证**（每层产出可断言中间产物）。

**不要用**，当且仅当——

- 一次性脚本 / PoC，生命周期只有几天，永不接新消费者。此时过度分层是负担。
- 你还没想清「事实」和「判断」的边界——先回去定义问题（见 00-Overview/SilverShield-Lessons 原则 1）。

## 落地 checklist

- [ ] 画出 7 层（Perception→Fact→Feature→Rule→Decision→Action→Presentation），标出每层在本领域的名词
- [ ] 事实层字段审查：有无夹带业务判断？
- [ ] 定义层间数据结构（事件 / 特征 / 风险 / 指令），并冻结
- [ ] 核心层只暴露 ABC / Protocol 接口，实现可替换
- [ ] 展示层只经白名单 + 只读消费核心
- [ ] 每层单测：断言其结构化产物
